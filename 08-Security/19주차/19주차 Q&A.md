## 2. 실제 작성한 Q2 피드백

**질문:** ALB Target Group에서 Healthy 상태는 무엇을 의미하는가?

**작성 답변:**
> 상태 이상 없이, 정상적으로 돌아갈 준비가 되어있는 상태를 의미합니다.

**피드백:** 방향은 맞지만 **어떤 검사 조건을 통과했는지** 설명하면 더 정확하다.

**보완 답변:**
> ALB Target Group의 Healthy는 등록 대상이 설정된 Health Check 조건을 충족했다는 뜻입니다. 예를 들어 지정된 HTTP 경로가 성공 코드 200을 반환하고 정상 임계값을 만족하면 Healthy로 판단합니다. 다만 이는 전체 애플리케이션의 모든 기능이 정상이라는 보장은 아닙니다.

**실습 연결:** AWS 콘솔에서 Target Group의 Healthy 상태를 확인하고, NACL 변경 전후 웹 응답과 대상 상태를 비교했다.

## 3. 핵심 암기 카드

### Security Group vs NACL
- **Security Group:** ENI 단위 적용, Stateful, 허용 규칙 중심.
- **NACL:** 서브넷 단위 적용, Stateless, 허용·거부 규칙 모두 지원.
- NACL에서는 요청뿐 아니라 **응답 방향 규칙 및 임시 포트**도 고려한다.

### IDS / IPS / WAF
- **IDS:** 침입 징후 탐지 및 경고.
- **IPS:** 인라인에서 탐지 및 차단 가능.
- **WAF:** HTTP/HTTPS 기반 웹 공격(SQLi, XSS 등) 방어.

### ALB Healthy
- **Healthy = 설정된 상태 검사 조건 통과.**
- 전체 서비스의 모든 기능이 정상이라는 의미는 아니다.

### Snort threshold
- 일정 시간 내 이벤트 발생 횟수 등을 기준으로 **경고 발생 빈도를 제어**한다.
- `count 5, seconds 10`은 10초·5회 조건을 표현하며, 실제 경고 동작은 threshold 유형에 따라 달라진다.

### SQL Injection vs XSS
- **SQLi:** 서버 측 SQL 쿼리의 의미를 조작.
- **XSS:** 사용자 브라우저에서 비신뢰 스크립트 실행 유도.

### Aurora Writer / Reader
- **Writer:** 쓰기 작업 담당, 읽기도 가능.
- **Reader:** 주로 읽기 요청 처리, 읽기 부하 분산 및 장애 조치 시 승격 후보 가능.

### 최소 권한 원칙
- IAM은 필요한 작업·리소스에만 권한 부여.
- 네트워크는 필요한 출발지·포트만 허용.

## 4. 추후 직접 풀어볼 압박 면접 (정답 미수록)

1. **NACL은 Stateless인데**, 클라이언트가 웹 서버의 80번 포트에 접속할 때 응답 트래픽은 어떻게 허용해야 할까?
   - 힌트: 클라이언트의 임시 포트(Ephemeral Port).
2. **ALB Target Group이 Healthy인데** 사용자가 웹사이트에 접속하지 못한다면 무엇부터 점검할까?
   - 힌트: 리스너, 보안 그룹, NACL, DNS.
3. **Snort IDS가 SQL Injection을 탐지했지만** 요청이 서버에 도달했다면 탐지 실패일까?
   - 힌트: IDS와 IPS의 역할 차이.
