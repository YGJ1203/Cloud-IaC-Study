### 3-3. 실습 검증 결과

- TCP SYN Flood Anomaly 로그 확인
- UDP Flood Anomaly 로그 확인
- ICMP Flood Anomaly 로그 확인
- clear_session 관련 로그 확인
- 정상 Ping 통신 확인
- HTTP 응답 확인

ICMP 테스트 결과:

- 전송 패킷: 1,000개
- 응답 패킷: 150개
- 패킷 손실률: 85%

공격성 트래픽 제한 결과를 확인하였다.

단, 패킷 손실률만으로 차단 원인을 확정하지 않고
Anomaly 로그 및 인터페이스별 패킷 흐름을 함께 분석한다.

HTTP 403 응답은 서버까지 HTTP 통신이 이루어졌음을
의미하지만, 정상적인 콘텐츠 제공 성공을 의미하지는 않는다.

## 4. Snort IDS 복습

### 4-1. Snort의 역할

네트워크 트래픽을 분석하여 사용자 정의 규칙 및
시그니처에 해당하는 의심스러운 패킷을 탐지한다.

### 4-2. 주요 디렉터리

```bash
/etc/snort/
/etc/snort/rules/
/var/log/snort/
```

### 4-3. 주요 명령어

```bash
# Snort 실행
snort -q -A console -b -c /etc/snort/snort.conf

# 네트워크 패킷 확인
tcpdump -nn -i eth0

# Snort 로그 디렉터리 확인
ls -l /var/log/snort/
```

※ 인터페이스 및 설정 파일 경로는 실습 환경에 따라 달라질 수 있다.

### 4-4. Snort Rule 구성 요소

| 항목 | 설명 |
|---|---|
| alert | 탐지 시 경고 발생 |
| msg | 경고 메시지 |
| content | 탐지할 문자열 또는 바이트 패턴 |
| sid | 규칙 식별 번호 |
| rev | 규칙 수정 버전 |
| threshold | 이벤트 발생 빈도 제어 |
| classtype | 공격 유형 분류 |

### 4-5. IDS와 IPS의 차이

- IDS: 의심스러운 트래픽 탐지 및 경고
- IPS: 의심스러운 트래픽 탐지 및 차단

Snort는 IDS로 활용할 수 있으며,
Inline 환경 및 적절한 설정에서는 IPS로도 활용할 수 있다.

## 10. 스택 프레임(Stack Frame)

### 10-1. 함수 호출 예제

```c
int add(int a, int b)
{
    return a + b;
}

int main()
{
    return add(6, 2);
}
```

### 10-2. 스택 프레임 구조

높은 메모리 주소
+---------------------+
| 매개변수 b          | EBP + 12
+---------------------+
| 매개변수 a          | EBP + 8
+---------------------+
| Return Address      | EBP + 4
+---------------------+
| 이전 EBP            | EBP
+---------------------+
| 지역변수 영역       | EBP - 4
+---------------------+
| 지역변수 영역       | EBP - 8
+---------------------+
낮은 메모리 주소

※ 일반적인 32비트 x86 cdecl 스택 프레임 예시이며,
컴파일러 최적화 및 호출 규약에 따라 달라질 수 있다.

### 10-3. 함수 진입 및 종료

```asm
pushl %ebp
movl %esp, %ebp
subl $8, %esp

# 함수 내부 연산

leave
ret
```

| 명령어 | 역할 |
|---|---|
| pushl %ebp | 기존 EBP 저장 |
| movl %esp, %ebp | 새로운 스택 프레임 기준 설정 |
| subl | 지역변수 공간 확보 |
| leave | 기존 스택 프레임 복원 |
| ret | 호출한 위치로 복귀 |

### 10-4. 핵심 개념

- 스택은 일반적인 x86 환경에서 낮은 주소 방향으로 성장한다.
- EBP는 함수의 스택 프레임 기준점이다.
- ESP는 현재 스택 최상단을 가리킨다.
- 반환 주소는 함수 종료 후 복귀할 위치이다.
- 정수 반환값은 일반적으로 EAX에 저장된다.

## 11. 메모리 주소 및 16진수

### 11-1. 메모리 주소 계산

```text
0xbfffe5dc + 4
= 0xbfffe5e0
```

16진수는 0~9와 A~F를 사용한다.

```text
0x0C = 12
0x0D = 13
0x0E = 14
0x0F = 15
0x10 = 16
```

### 11-2. 32비트 환경

- 1 Byte = 8 bit
- 4 Byte = 32 bit
- 일반적인 int 크기: 4 Byte
- 일반적인 포인터 크기: 4 Byte

4바이트 단위로 저장된 데이터는
메모리 주소를 4씩 증가시키면서 확인할 수 있다.

## 12. GDB 디버깅

### 12-1. GDB의 역할

프로그램 실행을 제어하면서 레지스터, 메모리,
함수 및 실행 흐름을 분석하는 디버거이다.

### 12-2. 주요 명령어 복습

```bash
# GDB 실행
gdb ./test

# main 함수에 중단점 설정
break main

# 프로그램 실행
run

# 함수 어셈블리 코드 확인
disassemble main

# 레지스터 확인
info registers

# 명령어 단위 실행
stepi
nexti

# 스택 메모리 확인
x/10wx $esp

# 현재 명령어 확인
x/i $eip

# 스택 프레임 확인
info frame

# 함수 호출 정보 확인
backtrace

# 실행 계속
continue

# 종료
quit
```

### 12-3. GDB 메모리 확인 문법

```bash
x/4wx $esp
```

- x: 메모리 검사
- 4: 출력할 데이터 개수
- w: 4바이트 단위
- x: 16진수 출력
- $esp: 검사할 메모리 시작 주소

### 12-4. 분석 순서

1. 프로그램 실행
2. 중단점 설정 및 확인
3. 어셈블리 코드 확인
4. 레지스터 값 확인
5. 스택 메모리 확인
6. 명령어 단위 실행
7. 실행 전후 값 변화 비교

## 13. C언어 제어문과 어셈블리어

### 13-1. if문

C언어 조건문은 어셈블리어에서
비교 명령어와 조건 분기 명령어로 구현될 수 있다.

주요 명령어:

- CMP
- TEST
- JE
- JNE
- JLE
- JGE
- JL
- JG

### 13-2. switch문

조건에 따라 서로 다른 실행 위치로 분기한다.

컴파일러에 따라 다음 방식으로 구현될 수 있다.

- CMP 및 조건 분기
- JMP
- Jump Table

### 13-3. for문 및 while문

반복문은 일반적으로 다음 구조로 구성된다.

1. 초기값 설정
2. 조건 비교
3. 반복문 내부 실행
4. 변수 증가 또는 감소
5. 조건 비교 위치로 이동

주요 명령어:

- MOV
- CMP
- ADD
- SUB
- JMP
- 조건 분기 명령어

### 13-4. main 함수 인자

```c
int main(int argc, char *argv[])
```

- argc: 전달된 인자의 개수
- argv: 전달된 인자 문자열의 배열

### 13-5. system 함수

```c
#include <stdlib.h>

int main()
{
    system("ls");
    return 0;
}
```

system 함수는 셸을 통해 명령어를 실행한다.

보안 관점에서는 검증되지 않은 외부 입력값이
system 함수에 전달되지 않도록 주의해야 한다.

이는 OS Command Injection 취약점과 연결된다.
