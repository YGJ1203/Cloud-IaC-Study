## 3. 주요 레지스터

| 레지스터 | 역할 |
|---|---|
| EAX | 산술 연산 및 함수 반환값 |
| EBX | 범용 데이터 저장 |
| ECX | 반복 횟수 및 범용 데이터 저장 |
| EDX | 산술 연산 보조 및 범용 데이터 저장 |
| EBP | 현재 함수의 스택 프레임 기준점 |
| ESP | 현재 스택의 최상단 주소 |
| EIP | 다음에 실행할 명령어의 주소 |
| EFLAGS | 연산 결과 및 CPU 상태 정보 |

### 주요 상태 플래그

- ZF(Zero Flag): 연산 결과가 0인지 확인
- SF(Sign Flag): 연산 결과의 부호 확인
- CF(Carry Flag): 자리올림 및 빌림 발생 여부 확인
- OF(Overflow Flag): 부호 있는 연산의 오버플로우 확인

## 4. 어셈블리어 기본 명령어

### 4-1. 데이터 이동 및 주소 계산

| 명령어 | 설명 |
|---|---|
| MOV | 데이터를 목적지로 복사 |
| LEA | 유효 메모리 주소 계산 |
| PUSH | 스택에 데이터 저장 |
| POP | 스택에서 데이터 추출 |

### MOV와 LEA의 차이

```asm
movl -4(%ebp), %eax
leal -4(%ebp), %eax
```

- MOV: 해당 메모리 주소에 저장된 값을 가져옴
- LEA: 해당 메모리 주소 자체를 계산하여 가져옴

### 4-2. 산술 연산 명령어

| 명령어 | 설명 |
|---|---|
| ADD | 덧셈 |
| SUB | 뺄셈 |
| IMUL | 부호 있는 곱셈 |
| IDIV | 부호 있는 나눗셈 |

```asm
movl $6, %eax
addl $2, %eax
```

- EAX에 6을 저장
- EAX에 2를 더함
- 최종 EAX 값은 8

### AT&T 문법의 특징

- 레지스터 앞에 `%` 사용
- 즉시값 앞에 `$` 사용
- 기본적으로 Source, Destination 순서
- `l` 접미사는 32bit 연산을 의미

## 5. 비교 및 조건 분기 명령어

### 5-1. 비교 명령어

| 명령어 | 설명 |
|---|---|
| CMP | 뺄셈을 기반으로 두 값을 비교하고 플래그 변경 |
| TEST | 비트 AND 연산을 기반으로 플래그 변경 |

CMP와 TEST는 연산 결과를 목적지에 저장하지 않고
상태 플래그를 변경하여 조건 분기에 활용한다.

### 5-2. 점프 명령어

| 명령어 | 의미 | 조건 |
|---|---|---|
| JMP | 무조건 분기 | 조건 없음 |
| JE / JZ | 같거나 결과가 0이면 분기 | ZF = 1 |
| JNE / JNZ | 다르거나 결과가 0이 아니면 분기 | ZF = 0 |
| JLE | 작거나 같으면 분기 | <= |
| JGE | 크거나 같으면 분기 | >= |
| JL | 작으면 분기 | < |
| JG | 크면 분기 | > |

※ JLE, JGE, JL, JG는 부호 있는 정수 비교에 사용된다.

### 조건 분기 예시

```asm
movl $6, %eax
cmpl $6, %eax
je equal
```

1. EAX에 6 저장
2. EAX와 6 비교
3. 두 값이 같으므로 ZF = 1
4. equal 위치로 분기

### 7-1. 실습 파일

### 7-2. 어셈블리어 변환

```bash

gcc -mpreferred-stack-boundary=2 -S -o lv3.a lv3.c
```

### 실행 파일 생성

```bash
gcc -mpreferred-stack-boundary=2 -o lv2 lv2.c
gcc -mpreferred-stack-boundary=2 -o lv3 lv3.c
gcc -mpreferred-stack-boundary=2 -o lv4 lv4.c
```

### GCC 옵션

| 옵션 | 설명 |
|---|---|
| -S | 어셈블리어 코드 생성 |
| -o | 출력 파일 이름 지정 |
| -mpreferred-stack-boundary=2 | 4Byte 스택 정렬 기준 지정 |

※ 일반적인 어셈블리어 파일 확장자는 .s이지만,
오늘 실습에서는 .a 확장자를 사용하였다.

### 7-3. lv2 어셈블리어 분석

```asm
pushl   %ebp
movl    %esp, %ebp
subl    $8, %esp
movl    $6, -4(%ebp)
movl    $2, -8(%ebp)
movl    $0, %eax
leave
ret
```

| 명령어 | 설명 |
|---|---|
| pushl %ebp | 기존 EBP 저장 |
| movl %esp, %ebp | 새로운 스택 프레임 기준점 설정 |
| subl $8, %esp | 지역변수 공간 8Byte 확보 |
| movl $6, -4(%ebp) | 첫 번째 지역변수에 6 저장 |
| movl $2, -8(%ebp) | 두 번째 지역변수에 2 저장 |
| movl $0, %eax | 반환값 0 설정 |
| leave | 스택 프레임 정리 |
| ret | 호출 위치로 복귀 |

### 7-4. 지역변수 개수에 따른 스택 변화

| 파일 | 지역변수 개수 | 확보된 스택 공간 |
|---|---:|---:|
| lv2 | 2개 | 8Byte |
| lv3 | 3개 | 12Byte |
| lv4 | 4개 | 16Byte |

```asm
# lv2
subl $8, %esp

# lv3
subl $12, %esp

# lv4
subl $16, %esp
```

오늘 실습 환경에서는 int형 지역변수가 하나씩 증가할 때마다
스택 할당 공간이 4Byte씩 증가하는 것을 확인하였다.

실제 스택 할당 크기는 컴파일러, 최적화 및 정렬 설정에 따라
달라질 수 있다.

### 7-5. 스택 메모리 구조

lv2의 두 지역변수 초기화 완료 상태를 기준으로 재구성하였다.

```text
높은 메모리 주소
+------------------------+
| 복귀 주소               | EBP + 4
+------------------------+
| 기존 EBP               | EBP
+------------------------+
| 지역변수 1 = 6          | EBP - 4
+------------------------+
| 지역변수 2 = 2          | EBP - 8 <- ESP
+------------------------+
낮은 메모리 주소
```

- EBP를 기준으로 지역변수 위치 확인
- ESP는 스택 최상단을 가리킴
- x86 스택은 낮은 메모리 주소 방향으로 확장

## 9. 함수 호출 및 인자 전달 실습

### 9-1. 실습 파일

- func.c
- func.a
- func

### 9-2. main 함수 분석

```asm
pushl   %ebp
movl    %esp, %ebp
pushl   $2
pushl   $6
call    func
addl    $8, %esp
movl    $0, %eax
leave
ret
```

### 실행 흐름

1. main 함수의 스택 프레임 생성
2. 함수 인자 2와 6을 스택에 저장
3. CALL 명령어로 func 함수 호출
4. 함수 실행 완료 후 main 함수로 복귀
5. 인자에 사용한 스택 공간 8Byte 정리
6. main 함수 반환값 0 설정
7. 프로그램 정상 종료

### 9-3. func 함수 분석

```asm
pushl   %ebp
movl    %esp, %ebp
movl    12(%ebp), %eax
addl    8(%ebp), %eax
leave
ret
```

- EBP + 8: 첫 번째 인자 6
- EBP + 12: 두 번째 인자 2
- EAX에 두 인자의 합인 8 저장
- EAX를 통해 함수 반환값 전달

※ 위 방식은 오늘 실습에서 사용한 32bit x86 호출 규약을
기준으로 하며, 64bit 환경에서는 인자 전달 방식이 다를 수 있다.

### 9-4. 함수 호출 시 스택 구조

```text
높은 메모리 주소
+------------------------+
| 두 번째 인자 = 2        | EBP + 12
+------------------------+
| 첫 번째 인자 = 6        | EBP + 8
+------------------------+
| 복귀 주소               | EBP + 4
+------------------------+
| 기존 EBP               | EBP
+------------------------+
낮은 메모리 주소
```

### 주요 명령어

| 명령어 | 역할 |
|---|---|
| CALL | 복귀 주소를 스택에 저장하고 함수 호출 |
| LEAVE | 현재 함수의 스택 프레임 정리 |
| RET | 스택의 복귀 주소를 이용해 호출 위치로 이동 |

## 10. main 함수 및 system 함수

### 10-1. main 함수

```c
int main(int argc, char *argv[])
```

- argc: 명령행 인자의 개수
- argv: 명령행 인자 문자열 배열
- argv[0]: 일반적으로 실행 프로그램 이름 또는 경로
- argv[1] 이후: 사용자가 전달한 인자

### 10-2. system 함수

```c
system("명령어");
```

- 문자열 형태의 명령어를 전달받음
- Linux 환경에서 셸을 통해 명령어 실행
- 실행 결과에 대한 상태값 반환

### 보안 관점

- 외부 입력값을 검증하지 않고 system 함수에 전달할 경우
  OS Command Injection 취약점이 발생할 수 있음
- 입력값 검증 및 안전한 프로세스 실행 방식 필요

※ main 및 system 함수는 오늘 학습 주제를 바탕으로
개념 위주로 정리하였다.

## 13. 시스템 보안과의 연관성

오늘 학습한 내용은 다음 시스템 보안 개념의 기초가 된다.

- Buffer Overflow
- Stack Overflow
- 메모리 변조
- 함수 복귀 주소 보호
- 프로그램 실행 흐름 분석
- 바이너리 분석 및 리버싱
- 악성코드 분석
- OS Command Injection
- ASLR
- NX / DEP
- Stack Canary

특히 스택 프레임, 지역변수, 함수 인자 및 복귀 주소의
관계를 이해하는 것이 메모리 취약점 분석의 핵심이다.

---

## 14. 오늘의 핵심 복습

- MOV는 값을 복사하고 LEA는 유효 주소를 계산한다.
- CMP와 TEST는 상태 플래그를 변경한다.
- 조건 점프는 상태 플래그를 기반으로 실행 흐름을 변경한다.
- EBP는 스택 프레임의 기준점이다.
- ESP는 현재 스택의 최상단을 가리킨다.
- EAX는 함수 반환값 전달 등에 사용된다.
- 지역변수와 전역변수는 일반적인 저장 영역이 다르다.
- CALL은 복귀 주소를 저장하고 함수를 호출한다.
- RET은 저장된 복귀 주소를 통해 호출 위치로 돌아간다.
- GDB를 통해 명령어 및 메모리 상태를 분석할 수 있다.
