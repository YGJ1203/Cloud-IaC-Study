## 3. Snort IDS 구성과 탐지

### 3.1 실행 명령 — 실제 기록

```bash
cd /etc/snort/rules
snort -q -A console -b -c /etc/snort/snort.conf &
```

- `-q`: 배너 등 일부 출력 억제(quiet).
- `-A console`: 탐지 경고를 콘솔에 출력.
- `-b`: 패킷을 tcpdump 형식으로 로깅하도록 지정.
- `-c`: 설정 파일 경로 지정.
- `&`: 셸 백그라운드 실행.
- 실제 셸 작업 번호 `[1]`, PID `2304`가 출력됨.

### 3.2 사용자 정의 ICMP Flood 탐지 규칙 — 기록된 핵심 조건

```snort
alert icmp any any -> $HOME_NET any (msg:"## ICMP Flooding Attack ##"; itype:8; icode:0; threshold:type both, track by_dst, count 100, seconds 1; sid:3000016; rev:1;)
```

> 위 규칙은 대화에서 확인된 규칙 내용의 **복습용 재구성**이다. 실제 저장된 `local.rules` 원본과 문자 단위 일치 여부는 별도 확인이 필요하다.

| 요소 | 의미 |
|---|---|
| `alert icmp` | ICMP 패킷 탐지 시 경고 |
| `any any -> $HOME_NET any` | 임의 송신지에서 HOME_NET 목적지 방향 |
| `itype:8` | ICMP Echo Request |
| `icode:0` | ICMP 코드 0 |
| `track by_dst` | 목적지 기준 발생 빈도 추적 |
| `count 100, seconds 1` | 1초 창에서 100건 임계 조건 |
| `sid:3000016` | 규칙 식별자 |
| `rev:1` | 규칙 개정 번호 |

`threshold:type both`는 이벤트 빈도 조건과 알림 억제 특성이 함께 적용되는 설정이다. **모든 패킷을 경고 1건씩 출력하는 구조가 아니다.** 정확한 경고 빈도는 Snort 버전/규칙 평가 상황에 따라 검증한다.

### 3.3 실제 탐지 경고

```text
10/30-14:44:33.716118 [**] [1:3000016:1] ## ICMP Flooding Attack ## [**] [Priority: 0] {ICMP} 1.2.3.4 -> 192.168.20.200
10/30-14:44:34.004318 [**] [1:3000016:1] ## ICMP Flooding Attack ## [**] [Priority: 0] {ICMP} 1.2.3.4 -> 192.168.20.200
10/30-14:44:35.004429 [**] [1:3000016:1] ## ICMP Flooding Attack ## [**] [Priority: 0] {ICMP} 1.2.3.4 -> 192.168.20.200
```

**확인된 결론:** SID 3000016이 실제로 경고를 발생시켰고, 패킷 헤더에 위조된 출발지 `1.2.3.4`가 나타났다. **실제 Kali의 주소가 1.2.3.4였다는 뜻은 아니다.** 또한 IDS 경고만으로 패킷 차단을 입증할 수 없다.

### 3.4 다른 Snort 탐지 주제 — 앞선 실습 내용

- SQL Injection 의심 문자열(`union`, `or`, `and`) 탐지. 문자열 탐지는 실제 취약점 악용 성공과 다름.
- Nmap Half Open(SYN), FIN, XMAS, NULL 스캔 탐지 규칙 실습.
- ICMP/SYN/UDP Flood 관련 규칙 작성 및 threshold 비교.
- 이 항목들은 현재 기록에 **모든 규칙 원문 및 전체 경고 로그가 첨부된 것은 아니므로**, 복습용 주제 목록으로 분류한다.

## 4. Kali hping3 ICMP Flood / IP Spoofing

### 4.1 사용자가 기록한 명령

```bash
hping3 -i eth0 --icmp 192.168.20.200 --faster --spoof 1.2.3.4
```

**문법 검증 필요:** hping3에서 인터페이스 지정은 일반적으로 대문자 `-I eth0` 또는 `--interface eth0`이다. 소문자 `-i`는 패킷 전송 간격 옵션이다. 위 명령은 **실습자가 기록한 원문 그대로** 보존했으며, 정상적인 인터페이스 지정 명령으로 간주하지 않는다.

**참고 문법(실행 확인 아님)**

```bash
# 격리된 허가 실습 환경에서만 옵션 문법 확인
hping3 --interface eth0 --icmp 192.168.20.200 --faster --spoof 1.2.3.4
```

- `--icmp`: ICMP 전송.
- `--faster`: 높은 패킷 전송 빈도(일반적으로 약 100pps).
- `--spoof 1.2.3.4`: IP 헤더의 출발지 주소 위조.
- 실제 응답은 원칙적으로 위조 주소로 향할 수 있어, 송신 호스트의 수신 통계는 환경에 따라 별도 검증해야 한다.

### 4.2 실제 출력

```text
38089 packets transmitted, 37886 packets received, 1% packet loss
round-trip min/avg/max = 0.9/17.1/1013.8 ms
len=46 ip=192.168.20.200 ttl=63 id=63737 icmp_seq=37886 rtt=8.7 ms
```

| 지표 | 값 |
|---|---:|
| 전송 | 38,089 |
| 수신 | 37,886 |
| 전송-수신 차이 | 203 |
| 계산상 응답률 | 약 99.47% |
| RTT 최소/평균/최대 | 0.9 / 17.1 / 1013.8 ms |

**주의:** `--spoof`가 포함된 실행에서 이렇게 많은 응답이 표시된 이유는 주어진 로그만으로 규명되지 않는다. 패킷 캡처, 실제 실행 인자, 라우팅 및 가상 네트워크 구성 확인이 필요하다. RTT 최댓값이 약 1초라는 사실만으로 서버 장애나 DoS 성공을 단정하지 않는다.

## 7. IPS · 국가 차단 · DoS/Flooding 방어

### 7.1 국가별 차단

Sophos의 국가 차단 설정 화면에서 국가별 `차단 해제` 또는 `모두 차단` 선택을 확인했다. **특정 국가 전체를 실제로 차단했는지에 대한 최종 적용 범위는 화면에 보이는 선택값까지만 기록한다.** 국가 차단은 지리정보 기반 필터이므로 VPN, 프록시, CDN 및 IP 위치정보 오류를 고려해야 한다.

### 7.2 IPS 공격 패턴

- `네트워크 보호 → 침입 방지 → 공격 패턴` 화면.
- 운영체제, HTTP 서버, 메일 서버, 데이터베이스 등 공격 패턴 그룹 확인.
- 화면의 그룹 동작은 `드롭`으로 표시.
- **중요:** 10월 29일 Executive Report에서 IPS 공격 이벤트/차단은 `0`. 설정 화면만으로 실제 IPS 차단이 일어났다고 기록하지 않는다.

### 7.3 Flooding 방지 화면

| 보호 | 사용 여부 | 원본 속도 임계값 | 대상 속도 임계값 |
|---|---|---:|---:|
| TCP SYN Flood | 활성 | 10 packets/s | 10 packets/s |
| UDP Flood | 활성 | 10 packets/s | 10 packets/s |
| ICMP Flood | **비활성** | 10 packets/s(입력값) | 20 packets/s(입력값) |

- 화면에서 TCP SYN/UDP는 저장 성공 메시지가 표시됨.
- ICMP는 체크박스가 꺼져 있으므로 숫자가 입력되어 있어도 활성화 상태로 해석하면 안 됨.
- **실무:** 초당 10패킷은 실제 서비스에서 정상 요청까지 오탐/차단할 수 있는 매우 낮은 실습값이다. 운영환경에서는 기준 트래픽과 서비스 특성을 먼저 측정한다.

|---|---|
| `open` | 서비스가 응답하여 포트가 열려 있다고 판단 |
| `closed` | 도달 가능하지만 포트에서 서비스가 수신 대기하지 않는 상태 |
| `filtered` | 필터링으로 열림/닫힘을 확정하기 어려움 |
| `open|filtered` | UDP 등에서 응답 부족으로 열림과 필터링을 구별하기 어려움 |

**관찰:** 15:44에는 1000개 모두 `filtered`; 16:29에는 53/80/443만 `open`이고 나머지 997개는 `filtered`. UDP 53은 `open|filtered`에서 `open`으로 변경. **정확한 원인은 중간 정책 변경 기록이 없어 확정 불가.**

서비스 버전이 매우 오래된 것으로 탐지되었으나, 이는 Nmap 핑거프린트 결과이며 패치 상태·취약점 악용 가능성을 단독으로 확정하지 않는다.

## 10. Ping · TCP SYN Flood · UDP Flood — 실제 콘솔

### 10.1 Ping

```bash
ping -c 3 192.168.20.200
```

```text
3 packets transmitted, 0 received, 100% packet loss, time 2030ms
```

**해석:** ICMP Echo Reply가 수신되지 않음. ICMP 차단 정책, 호스트 설정, 라우팅 등 다양한 원인 가능. **Sophos ICMP Flood 보호가 활성화되었다는 증거는 아님.**

### 10.2 TCP SYN Flood

```bash
# 실제 기록 — 격리된 승인 실습망에서만 수행
hping3 --interface eth0 --syn -p 80 192.168.20.200 --flood
```

```text
hping in flood mode, no replies will be shown
84951 packets transmitted, 0 packets received, 100% packet loss
```

### 10.3 UDP Flood

```bash
# 실제 기록 — 격리된 승인 실습망에서만 수행
hping3 --interface eth0 --udp -p 53 192.168.20.200 --flood
```

```text
hping in flood mode, no replies will be shown
57769 packets transmitted, 0 packets received, 100% packet loss
```

| 시험 | 대상 포트 | 전송 패킷 |
|---|---:|---:|
| TCP SYN | 80/tcp | 84,951 |
| UDP | 53/udp | 57,769 |
| **합계** | — | **142,720** |

**핵심 함정:** `--flood` 모드는 응답 표시를 생략한다. 따라서 `0 packets received`, `100% packet loss`는 **UTM이 모든 패킷을 차단했다는 증거가 아니다.** 방어 성능은 UTM 로그의 해당 시각·송신지·목적지·프로토콜·드롭 사유와 대상 서버 자원 상태를 대조해야 한다.

## 12. 결과 해석 주의점과 트러블슈팅

| 상황 | 잘못된 결론 | 정확한 판단/추가 확인 |
|---|---|---|
| Snort 경고 발생 | 공격이 차단됨 | IDS 경고 확인; 차단 여부는 별도 확인 |

1. 실습 시작/종료 시각과 적용한 방화벽 규칙 ID를 기록.

## 13. 실무·면접 Q&A

**Q1. IDS와 IPS의 차이는?**  
A. IDS는 침입 의심 행위를 탐지하고 경고하는 것이 기본 역할이다. IPS는 트래픽 경로에서 정책에 따라 차단할 수 있다. 실제 동작은 배치 방식과 설정에 좌우된다.

**Q2. Snort 경고에 `1.2.3.4`가 나타나면 실제 공격자 IP인가?**  
A. 아니다. 패킷 헤더의 출발지 주소이며 스푸핑되었을 수 있다. 실제 송신지 확인에는 네트워크 경로와 장비 로그가 필요하다.

**Q3. Nmap의 `filtered`와 `closed`는?**  
A. `filtered`는 필터링 때문에 포트 상태를 확정할 수 없고, `closed`는 대상이 연결을 수용하지 않는 응답을 보내 닫힌 것으로 판단되는 상태다.

**Q4. TCP SYN Flood의 원리는?**  
A. TCP 연결 수립에 쓰이는 SYN 패킷을 대량 발생시켜 연결 상태 관리 및 자원을 압박할 수 있다. SYN Cookies, 속도 제한, 적절한 방화벽/IPS 정책 등을 고려한다.

**Q5. UDP Flood와 ICMP Flood의 차이는?**  
A. UDP Flood는 비연결형 UDP 패킷을, ICMP Flood는 ICMP 메시지를 다량 전송한다. 공격 영향은 대상 처리능력과 네트워크 구조에 따라 다르다.

**Q6. `--flood` 실행 후 `100% packet loss`면 방어 성공인가?**  
A. 아니다. hping3 flood 모드는 응답 표시를 생략한다. 실제 차단은 장비 로그와 서비스 상태를 통해 판단한다.

**Q7. Sophos 방화벽 드롭 4,404건과 IPS 0건은 모순인가?**  
A. 아니다. 방화벽과 IPS는 서로 다른 정책 엔진·카운터다. 방화벽이 드롭했어도 IPS 이벤트는 0일 수 있다.

**Q8. `count 100, seconds 1`은 무엇인가?**  
A. 설정된 추적 기준에서 1초 동안 이벤트 발생 횟수 100건을 임계 조건으로 평가하는 것이다. 경고 건수와 전체 패킷 수는 일치하지 않을 수 있다.

**Q9. 웹 필터링 차단 페이지로 무엇을 증명할 수 있나?**  
A. 해당 URL 요청이 당시 정책에 따라 차단되었음을 증명한다. 모든 카테고리의 필터링 성공을 의미하지는 않는다.

**Q10. 보안장비 테스트에서 가장 중요한 증거는?**  
A. 공격/시험 트래픽의 생성 로그, 장비 정책 및 적용 시각, 탐지/드롭 로그, 대상 서비스 상태를 서로 맞춰 보는 것이다.
