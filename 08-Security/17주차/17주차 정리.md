## 2. 개념 핵심 정리

| 개념 | 핵심 | 예시 |
|---|---|---|
| Sniffing | 네트워크 트래픽을 관찰·수집 | 패킷 캡처 |
| Spoofing | IP, ARP, DNS 등 식별·응답 정보를 위조 | DNS 응답 변조 |
| Flooding | 많은 패킷을 빠르게 전송 | ICMP/UDP Flood |
| DoS | 단일 또는 제한된 출처의 서비스 방해 | 대량 요청으로 자원 고갈 |
| DDoS | 여러 분산 출처에서 서비스 방해 | 봇넷 기반 대량 트래픽 |
| IDS | 의심 트래픽 탐지 및 경보 | Snort 탐지 규칙 |
| IPS | 인라인 배치 등 조건에서 탐지 후 차단 | Snort IPS 모드 등 |
| ACL | 조건에 맞는 트래픽 허용·거부 | Cisco Extended ACL |

**중요:** Flooding은 트래픽 발생 기법이며, DoS/DDoS는 서비스 가용성을 침해하는 공격 목적·결과를 가리킨다. 스푸핑은 수동 공격이 아니라 일반적으로 능동적 조작에 해당한다.

### 수동 공격과 능동 공격

- 수동(Passive): 관찰·도청 중심, 패킷 내용을 변경하지 않음.
- 능동(Active): 위조·변조·주입·서비스 방해 등 통신에 개입.
- 주의: 스니핑도 권한 없이 수행하면 불법일 수 있다.

## 3. 10월 27일 — hping3 및 Ettercap

### 3.1 ICMP Flood와 출발지 IP 위조

실습 기록: Kali `eth1` → 대상 `192.168.20.200`, 위조 출발지 `192.168.20.30`, 약 **299,302개** 패킷 전송 관측.

- `--flood`: 응답 대기나 일반적인 전송 간격 없이 빠르게 패킷 전송.
- `--spoof`: IP 헤더의 출발지 주소를 지정값으로 위조.
- Wireshark의 `icmp` 필터로 ICMP 트래픽 증가를 확인.
- **주의:** 패킷 전송 수는 서비스 중단 성공을 의미하지 않는다. 서비스 응답성, 자원 사용량, 손실률 등을 별도로 확인해야 한다.

### 3.2 DNS Spoofing

Ettercap에서 호스트 스캔, 대상 지정, `dns_spoof` 플러그인을 실습. `etter.dns`에 A/PTR 매핑을 추가하는 방식 확인.

```text
# 실습용 예시 — 실제 악성 목적지·서비스 도메인 대신 안전한 예약 도메인 사용
example.test       A       192.0.2.50
*.example.test     A       192.0.2.50
example.test       PTR     192.0.2.50
```

- A 레코드: 이름 → IPv4 주소.
- PTR 레코드: 역방향 DNS에 쓰이는 레코드. 실제 역방향 조회는 `in-addr.arpa` 네임스페이스와 질의 형태에 좌우되므로 위 단순 매핑이 표준 DNS 역방향 존 설정과 동일한 것은 아니다.
- DNS Spoofing 방어: 신뢰 가능한 DNS 검증, DNSSEC(검증 경로가 지원될 때), 암호화된 DNS, 네트워크 세그먼트 보호, TLS 인증서 검증.

## 4. 10월 28일 — Flooding, Nmap/Zenmap

### 4.1 공격 트래픽 관찰

- UDP Flood: 실습 대상 `192.168.20.200`, 목적지 UDP/53, 약 **719,480개** 패킷 전송 기록.
- Python 실습: `icmp_flood.py` 약 100개, `icmp_land.py` 약 50개 전송 기록.
- ICMP LAND: 출발지와 목적지의 위조된 동일성 등 비정상 패킷 특성을 이해하는 실습. 현대 시스템에서 실제 취약 여부는 별도 검증 필요.
- Wireshark에서 패킷 빈도, 출발지·목적지, 프로토콜을 비교해 정상/비정상 패턴 분석.

### 4.2 Nmap 주요 옵션

```bash
# 허가된 실습망에서만 실행
nmap -sS -sV 192.168.20.200
nmap -sU -p 53 192.168.20.200
nmap -T4 -A -v 192.168.20.200
```

| 옵션 | 의미 |
|---|---|
| `-sS` | TCP SYN 스캔 |
| `-sV` | 서비스/버전 식별 |
| `-sU` | UDP 스캔 |
| `-p 53` | 53번 포트 지정 |
| `-T4` | 빠른 타이밍 템플릿 |
| `-A` | OS 탐지, 버전 탐지, 기본 스크립트 및 traceroute 활성화 |
| `-v` | 상세 출력 |

### 4.3 당시 관찰 결과

- 대상 `192.168.20.200` 호스트 활성 상태 확인.
- UDP/53 `open`, UDP/54 `closed` 기록.
- TCP 개방 포트 13개 기록: **21, 22, 23, 25, 53, 80, 110, 111, 143, 443, 993, 995, 3306**.
- 예시 서비스 식별: FTP(vsftpd 2.0.5), SSH, Telnet, SMTP, DNS(BIND), HTTP(Apache 2.2.3), POP3, RPC, IMAP, HTTPS, MySQL.
- FTP 익명 접근 표시, MySQL `unauthorized` 표시 등은 **추가 검증 대상**이지 곧바로 취약점 악용 성공의 증거는 아니다.

**면접 포인트:** `open`은 서비스 응답이 관찰되었다는 뜻, `closed`는 도달 가능하지만 해당 포트가 수신하지 않는다는 뜻, `filtered`는 필터링 때문에 개방 여부를 확정하기 어렵다는 뜻이다. UDP의 `open|filtered`는 응답 부재만으로 두 상태를 구분할 수 없을 때 사용된다.

## 5. 10월 29일 — 5-Tuple 및 Cisco ACL

### 5.1 5-Tuple

1. Source IP (출발지 IP)
2. Destination IP (목적지 IP)
3. Protocol (프로토콜)
4. Source Port (출발지 포트)
5. Destination Port (목적지 포트)

TCP/UDP 연결 식별·방화벽 정책·로그 분석에서 중요하다. ICMP처럼 포트가 없는 프로토콜은 타입·코드 등 다른 필드를 활용한다.

### 5.2 Extended ACL 기본 구조

```cisco
conf t
ip access-list extended In-Filter
 deny ip 192.168.20.0 0.0.0.255 host <MASKED_BLOCKED_IP_1> log-input
 deny ip 192.168.20.0 0.0.0.255 host <MASKED_BLOCKED_IP_2> log-input
 500 permit ip any any
exit
interface e0/1
 ip access-group In-Filter in
end
```

> 위 `<MASKED_BLOCKED_IP_*>`는 설명용 자리표시자이므로 실제 IOS에 그대로 입력하면 안 된다. 원본 실습의 불법 사이트 도메인·IP는 의도적으로 비식별 처리했다.

- `deny ip`: IP 프로토콜 전체 대상으로 차단(특정 TCP/UDP 포트 한정이 아님).
- `0.0.0.255`: `/24`에 해당하는 와일드카드 마스크.
- `host`: 특정 목적지 IP 한 개.
- `log-input`: 매칭 패킷 로깅과 입력 인터페이스 관련 정보 기록(플랫폼·기능에 따라 출력 차이).
- `500 permit ip any any`: 시퀀스 번호 500으로 나머지 IP 트래픽 허용.
- `in`: 지정 인터페이스의 **입력 방향**에 ACL 적용.
- ACL은 일반적으로 위에서 아래로 처음 매칭되는 규칙이 적용되며, 끝에는 암묵적 거부가 있다.

### 5.3 확인 명령

```cisco
show ip access-lists
show ip interface e0/1
show running-config | section ip access-list
```

**주의:** 목적지 IP 차단은 공유 IP/CDN 환경에서 정상 서비스까지 영향을 줄 수 있다. 실제 운영에서는 DNS/URL 필터, 프록시, NGFW 등과 정책 범위를 비교해야 한다.

## 6. 10월 30일 — Snort 및 스캔 재검증

### 6.1 기록된 실습 결과

```text
nmap -sS -sV 192.168.20.200
Host is up (0.00080s latency).
All 1000 scanned ports on 192.168.20.200 are filtered
```

```text
nmap -sU -p 53 192.168.20.200
Host is up
```

두 번째 UDP 스캔의 **최종 포트 상태는 제공된 기록에서 확인되지 않았으므로 기재하지 않는다.**

### 6.2 결과 해석

- `Host is up`: Nmap이 호스트가 살아 있다고 판단했다.
- `All 1000 scanned ports ... filtered`: 기본 TCP 스캔 범위의 1000개 포트에 대해 필터링으로 개방 여부를 확인할 수 없었다.
- **이전 13개 TCP 포트가 open이었던 기록과 비교하면** 네트워크 경로·ACL·방화벽·IPS 정책 변화 등으로 응답이 차단되었을 가능성이 있다.
- 그러나 `filtered` 결과만으로 **Snort가 실제로 차단했다**고 단정할 수는 없다. Snort 운영 모드, 룰 매칭 로그, 방화벽 정책, 패킷 캡처를 함께 확인해야 한다.

### 6.3 Snort IDS/IPS 구분

| 구분 | IDS | IPS |
|---|---|---|
| 목적 | 탐지·알림 | 탐지·차단 |
| 배치 | 미러링/SPAN 등 패시브 가능 | 일반적으로 인라인 필요 |
| 결과 | 경보·로그 | 드롭·리젝트 등 정책 수행 가능 |
| 확인 | Alert 및 탐지 이벤트 | Alert + 실제 차단/드롭 증거 |

**검증 체크리스트**

- [ ] Snort가 IDS인지 IPS인지 확인
- [ ] 적용 룰의 SID, action, 조건 확인
- [ ] Snort 경보 및 드롭 카운터 확인
- [ ] ACL/방화벽 정책 변경 여부 확인
- [ ] 동일 조건에서 스캔 전후 비교
- [ ] Wireshark로 SYN/SYN-ACK/RST/ICMP 응답 패턴 비교
- [ ] 대상 서비스의 정상 응답성도 함께 확인

## 8. 면접 대비 Q&A 15선

**Q1. 스니핑과 스푸핑의 차이는?**  
A. 스니핑은 트래픽 관찰, 스푸핑은 식별정보 또는 응답을 위조하는 행위다.

**Q2. DoS와 DDoS의 차이는?**  
A. 공격 트래픽의 출처가 단일·제한적인지, 다수의 분산된 시스템인지가 핵심 차이다.

**Q3. SYN 스캔 원리는?**  
A. SYN을 전송하고 SYN-ACK, RST, 무응답/오류를 바탕으로 포트 상태를 판단한다.

**Q4. filtered가 의미하는 것은?**  
A. 필터링 등으로 포트가 열려 있는지 확정하기 어렵다는 뜻이다.

**Q5. UDP 스캔이 TCP보다 해석하기 어려운 이유는?**  
A. UDP는 연결 수립 절차가 없고 열린 포트도 응답하지 않을 수 있다.

**Q6. IDS와 IPS의 가장 큰 차이는?**  
A. IDS는 주로 탐지·알림, IPS는 인라인 차단 기능까지 수행할 수 있다.

**Q7. ACL의 implicit deny란?**  
A. 명시적 허용 규칙에 매칭되지 않는 트래픽은 끝에서 암묵적으로 거부된다.

**Q8. ACL in/out은 어떻게 구분하는가?**  
A. 라우터 인터페이스 기준으로 들어오는 패킷은 in, 나가는 패킷은 out이다.

**Q9. 와일드카드 마스크 0.0.0.255의 의미는?**  
A. 마지막 옥텟의 8비트를 비교하지 않으며, 일반적인 /24 네트워크 매칭에 쓰인다.

**Q10. 5-Tuple은 무엇인가?**  
A. 출발지 IP, 목적지 IP, 프로토콜, 출발지 포트, 목적지 포트다.

**Q11. DNS Spoofing의 위험은?**  
A. 사용자가 의도하지 않은 서버로 연결되도록 유도할 수 있다.

**Q12. DNSSEC는 무엇을 보장하는가?**  
A. 검증된 DNS 데이터의 출처 인증과 무결성을 지원하지만 전송 자체의 암호화는 제공하지 않는다.

**Q13. Snort alert가 있으면 차단 성공인가?**  
A. 아니다. 경보는 탐지 증거이고 차단은 별도의 드롭/인라인 증거가 필요하다.

**Q14. 포트 스캔 결과가 open에서 filtered로 바뀌었다면?**  
A. ACL·방화벽·IPS·라우팅·호스트 설정 등 여러 가능성을 로그와 패킷으로 구분한다.

**Q15. 운영 환경에서 공격 재현 시 우선사항은?**  
A. 명시적 승인, 테스트 범위, 영향 최소화, 롤백 및 모니터링 계획이다.

## 9. 시험 직전 암기 카드

- `-sS`: TCP SYN / `-sU`: UDP / `-sV`: 서비스 버전 / `-A`: 종합 탐지 / `-T4`: 타이밍.
- `open` ≠ 취약점 확정 / `filtered` ≠ 호스트 다운.
- IDS = 탐지 / IPS = 탐지 + 조건부 차단.
- ACL = 순서 중요, 첫 매칭, 암묵적 거부.
- `in/out` = 라우터 인터페이스 기준.
- DNS A = 이름→IPv4 / PTR = 역방향 조회.
- 패킷 수 증가 ≠ DoS 성공.
- Snort 경보 발생 ≠ IPS 차단 성공.
