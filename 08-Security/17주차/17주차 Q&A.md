## 1. 네트워크 공격 기본

### Q1. 스니핑과 스푸핑의 차이는?
**답:** 스니핑은 통신 데이터를 관찰·수집하는 행위이고, 스푸핑은 IP·ARP·DNS 등 식별정보나 응답을 위조하는 행위입니다. 스니핑은 주로 수동적, 스푸핑은 주로 능동적 공격에 해당합니다.

### Q2. DoS와 DDoS는 어떻게 다른가요?
**답:** DoS는 서비스의 가용성을 떨어뜨리는 공격 전반이고, DDoS는 다수의 분산된 공격 출발지에서 공격을 수행하는 형태입니다. 단순히 패킷이 많다고 무조건 DDoS는 아닙니다.

### Q3. Flooding과 Spoofing을 함께 사용할 수 있나요?
**답:** 가능합니다. Flooding은 대량 트래픽을 보내는 방식이고, Spoofing은 패킷의 출발지 주소 등을 위조하는 방식이므로 서로 다른 축의 개념입니다. 위조된 주소는 공격자 추적을 어렵게 만들 수 있습니다.

### Q4. DNS Spoofing의 징후와 대응책은?
**답:** 의도한 도메인이 비정상 IP로 해석되거나 예상하지 못한 페이지로 연결될 수 있습니다. 신뢰할 수 있는 DNS 설정, DNSSEC 검증(지원 환경), 암호화된 DNS 전송, 네트워크 감시, HTTPS 인증서 검증 등이 대응에 도움이 됩니다. DNSSEC는 DNS 데이터의 진위를 검증하지만 전송 암호화 자체를 제공하지는 않습니다.

## 2. 탐지와 스캔

### Q5. Nmap의 -sS, -sU, -sV, -A 옵션을 설명해 보세요.
**답:** `-sS`는 TCP SYN 스캔, `-sU`는 UDP 스캔, `-sV`는 서비스 버전 탐지, `-A`는 OS 탐지·버전 탐지·기본 스크립트 스캔·traceroute 등을 활성화합니다. 권한과 환경에 따라 일부 탐지 결과가 달라질 수 있습니다.

### Q6. open, closed, filtered 상태의 차이는?
**답:** open은 대상 포트에서 서비스가 응답하는 상태, closed는 도달 가능하지만 해당 포트에서 수신 서비스가 없는 상태, filtered는 필터링 때문에 포트가 열렸는지 판별하기 어려운 상태입니다.

### Q7. TCP 1000개 포트가 모두 filtered라고 나오면 서비스가 모두 중지된 것인가요?
**답:** 아닙니다. 방화벽이나 ACL이 탐지 패킷 또는 응답을 차단하여 판단할 수 없다는 의미입니다. 차단 전후 스캔 결과를 비교하고 방화벽 규칙과 로그를 확인해야 합니다.

### Q8. UDP 포트 스캔에서 open|filtered가 나오는 이유는?
**답:** UDP는 TCP처럼 연결 수립 절차가 없어 응답이 없는 경우 서비스가 열렸는지 필터링되었는지 구별하기 어렵습니다. 애플리케이션별 프로브와 패킷 캡처가 필요할 수 있습니다.

### Q9. Wireshark와 Snort의 차이는?
**답:** Wireshark는 패킷 캡처 및 상세 분석에 특화되어 있고, Snort는 규칙 기반으로 네트워크 트래픽을 탐지하며 구성에 따라 IPS로 차단도 수행할 수 있습니다. 패킷 분석 도구와 탐지·차단 시스템의 목적이 다릅니다.

## 3. 접근 통제와 방어

### Q10. ACL의 5-Tuple은?
**답:** 출발지 IP, 목적지 IP, 프로토콜, 출발지 포트, 목적지 포트입니다. 단, 일반적인 확장 ACL 규칙이 항상 다섯 요소를 모두 명시하는 것은 아닙니다.

### Q11. Cisco 확장 ACL에서 마지막 permit ip any any가 중요한 이유는?
**답:** ACL에는 암묵적인 deny가 있으므로 명시적 허용 규칙이 없으면 나머지 트래픽까지 차단될 수 있습니다. 다만 광범위한 허용은 최소 권한 원칙과 상충할 수 있어 운영 정책에 맞게 범위를 제한해야 합니다.

### Q12. 인바운드 ACL을 인터페이스에 적용하면 언제 검사하나요?
**답:** 해당 인터페이스로 들어오는 패킷에 대해 라우팅 전달 전에 적용된 ACL 규칙을 평가합니다. 실제 처리 순서는 플랫폼과 기능에 따라 차이가 있을 수 있습니다.

### Q13. IDS와 IPS의 차이는?
**답:** IDS는 침입 징후를 탐지·경고하는 데 초점이 있고 IPS는 트래픽 경로상에서 악성 패킷을 차단할 수 있습니다. IPS의 오탐은 정상 서비스에 영향을 줄 수 있어 정책 검증이 중요합니다.

### Q14. AWS Security Group과 Network ACL의 차이는?
**답:** Security Group은 ENI/리소스 수준의 상태 저장(stateful) 필터이며 허용 규칙 중심입니다. Network ACL은 서브넷 수준의 비상태 저장(stateless) 필터이며 허용·거부 규칙과 순서가 있습니다. NACL에서는 반환 트래픽도 고려해야 합니다.

### Q15. AWS WAF와 Security Group은 무엇이 다른가요?
**답:** WAF는 지원되는 HTTP(S) 서비스의 웹 요청을 규칙에 따라 검사하고, Security Group은 IP·프로토콜·포트 수준에서 트래픽을 허용합니다. SQL 인젝션 등 웹 요청 패턴 대응에는 WAF가 더 직접적입니다.

## 4. 시나리오형 실무 면접

### Q16. Nmap 스캔 후 모든 TCP 포트가 filtered로 바뀌었습니다. 어떻게 설명하겠습니까?
**답:** '접속 가능한 서비스가 모두 종료되었다'고 단정하지 않고 ACL·방화벽 차단의 가능성을 우선 검토합니다. 적용 전후 규칙, 방향, 출발지·목적지, 로그, 정상 서비스 접근 여부를 함께 검증합니다.

### Q17. 비정상적인 ICMP 트래픽 급증을 발견했다면?
**답:** 정상 모니터링 트래픽인지 먼저 구분하고 패킷 수·속도·출발지 분포·시각·서버 자원 사용률을 확인합니다. 승인된 정책에 따라 속도 제한이나 필터링을 적용하고, 영향과 오탐 여부를 모니터링합니다.

### Q18. DNS 응답이 위조된 것으로 의심되면?
**답:** 대상 단말의 DNS 서버 설정, 질의·응답 패킷, 캐시, 인증서 오류, 기준 DNS와의 응답 차이를 확인합니다. 의심 단말을 격리하고 DNS 설정 및 ARP 테이블 변조 여부를 조사하며 로그와 증거를 보존합니다.

### Q19. Snort 경고가 발생하면 곧바로 공격 성공이라고 볼 수 있나요?
**답:** 아닙니다. 규칙 매칭은 공격 시도 또는 의심 행위의 탐지일 수 있습니다. 패킷, 서버 로그, 세션, 대상 자산 상태, 오탐 가능성을 연계해 실제 영향 여부를 판단합니다.

### Q20. 네트워크 보안 실습 경험을 면접에서 어떻게 설명할까요?
**답변 예시:** '격리된 실습망에서 Nmap으로 서비스 노출 상태를 확인하고, ACL 및 보안 규칙 적용 전후 스캔 결과를 비교했습니다. 특히 TCP 포트가 filtered로 표시된 결과를 단순한 서비스 중단이 아닌 필터링 효과의 관점에서 해석했고, Wireshark·Snort 로그를 함께 확인하며 탐지와 차단의 차이를 학습했습니다.'

## 5. 명령어 및 설정 복습

```bash
# 승인된 실습 대상의 TCP SYN 및 서비스 버전 확인
nmap -sS -sV 192.168.20.200

# 승인된 실습 대상의 DNS UDP 포트 확인
nmap -sU -p 53 192.168.20.200

# TCP 포트 상태 비교용 스캔
nmap -T4 -A -v 192.168.20.200
```

```text
! 실제 외부 사이트의 도메인/IP는 기록하지 않고 마스킹
conf t
ip access-list extended In-Filter
 deny ip 192.168.20.0 0.0.0.255 host <MASKED_BLOCKED_IP> log-input
 500 permit ip any any
interface e0/1
 ip access-group In-Filter in
end
```

**주의:** `<MASKED_BLOCKED_IP>`는 문서화용 플레이스홀더이며 IOS에 그대로 입력할 수 없습니다. 실제 적용 시 승인된 실습용 IP로 대체해야 합니다. `permit ip any any`는 교재·실습의 동작 확인용 예시로, 운영 환경에서는 허용 범위를 최소화해야 합니다.
