### 2.1 Nmap 서비스 탐지

실습 대상 `192.168.20.200`에서 관찰한 주요 서비스:

| 포트 | 서비스 | 보안 관점 |
|---|---|---|
| 21/tcp | FTP | 평문 인증 여부, 익명 접근 확인 |
| 22/tcp | SSH | 인증 정책, 버전 및 접근 제한 |
| 23/tcp | Telnet | 평문 원격접속 위험 |
| 25/tcp | SMTP | 릴레이 설정 및 인증 점검 |
| 53/tcp | DNS | 재귀 질의 및 정보 노출 점검 |
| 80/tcp | HTTP | 구형 웹서버·애플리케이션 취약점 |
| 110/tcp | POP3 | 암호화되지 않은 인증 가능성 |
| 111/tcp | rpcbind | RPC 서비스 노출 점검 |
| 143/tcp | IMAP | TLS 적용 여부 |

| 993/tcp | IMAPS | 암호화된 메일 접근 |
| 995/tcp | POP3S | 암호화된 메일 접근 |
| 3306/tcp | MySQL | 외부 접근 제어 및 인증 |

실습에서 식별된 일부 버전은 vsftpd 2.0.5, OpenSSH 4.3, Sendmail 8.13.8, BIND 9.3.6-P1, Apache 2.2.3 등이었다. **서비스 버전만으로 취약점 악용 가능성을 확정할 수는 없다.** 패치 백포트, 실제 구성 및 접근 조건을 확인해야 한다.

```bash
# 승인된 실습 호스트에 한해 수행
nmap -sS -sV 192.168.20.200
nmap -sU -p 53 192.168.20.200
```

- `-sS`: TCP SYN 스캔
- `-sV`: 서비스·버전 탐지
- `-sU`: UDP 스캔
- `open|filtered`: UDP 응답만으로 열린 상태와 필터링 상태를 구분하지 못함
- `filtered`: 방화벽·ACL 등의 영향으로 상태 판단에 필요한 응답을 얻지 못함

### 2.2 SUID와 권한 관리

```bash
find / -perm -4000 2>/dev/null
```

- SUID가 설정된 실행 파일은 실행 중 파일 소유자의 유효 권한으로 동작할 수 있다.
- SUID 자체가 악성이라는 뜻은 아니다. `passwd`, `sudo` 등 정상적인 용도가 존재한다.
- 불필요한 SUID 바이너리, 잘못된 소유권, 취약한 프로그램은 권한 상승 위험을 키운다.
- 점검 시 파일 소유자·권한·패키지 무결성·업데이트 상태를 함께 확인한다.

## 4. 11월 5~6일 — SQL Injection 집중 학습

### 4.1 SQL Injection이란?

사용자가 입력한 문자열이 SQL 명령문의 **데이터가 아니라 SQL 구문 일부로 해석**될 때 발생할 수 있는 취약점이다.

- 원인: 문자열 연결로 SQL을 동적으로 조립하는 구현
- 영향: 인증 우회, 데이터 조회·변조, 정보 노출 등
- 핵심 방어: **파라미터 바인딩(Prepared Statement)**, 최소 권한, 입력 검증, 오류 메시지 관리

### 4.2 로그인 폼 실습

실습용 `SQL Injection (Login Form/Hero)` 화면에서 정상 계정 로그인과 조건식 조작에 따른 응답 차이를 관찰했다. 예를 들어 정상 계정 `neo`로 로그인하면 사용자별 환영 문구와 비밀 문구가 출력되었다. 다른 레코드를 선택하면 다른 사용자 정보가 표시될 수 있다는 점을 확인했다.

실습에서 다룬 `OR` 조건과 `LIMIT`는 다음처럼 이해한다.

- `OR`: WHERE 절의 조건을 결합하며, 잘못 사용되면 원래 인증 조건을 무력화할 수 있다.
- `LIMIT offset, count`: 결과 집합에서 시작 위치와 반환 개수를 지정한다. 시작 위치는 0부터 센다.
- SQL 주석 문법: 원래 쿼리의 뒤쪽 구문이 무시되는 상황을 만들 수 있다.

**중요:** 실제 로그인 우회 가능 여부는 쿼리 구조·DBMS·애플리케이션 로직에 따라 달라진다.

### 4.3 UNION SELECT의 원리

`UNION`은 두 SELECT 결과를 결합한다. 결과 열의 개수가 같고 각 열의 데이터 형식이 호환되어야 한다.

```sql
-- 정상적인 SQL 문법 설명용 예시
SELECT id, name FROM employees
UNION
SELECT id, name FROM contractors;
```

실습에서는 반환 열 수를 확인한 뒤 결과에 문자열이 표시되는 위치를 관찰했다. **열 개수와 출력 위치가 일치한다는 사실은 데이터가 노출될 수 있는 경로를 설명**한다.

### 4.4 information_schema

MySQL의 `information_schema`는 DB 객체에 대한 메타데이터를 제공한다.

| 메타데이터 뷰 | 주요 컬럼 | 의미 |
|---|---|---|
| `information_schema.SCHEMATA` | `SCHEMA_NAME` | 데이터베이스 목록 |
| `information_schema.TABLES` | `TABLE_SCHEMA`, `TABLE_NAME` | 스키마별 테이블 |
| `information_schema.COLUMNS` | `TABLE_SCHEMA`, `TABLE_NAME`, `COLUMN_NAME` | 테이블별 컬럼 |

```sql
-- 허가된 데이터베이스에서 메타데이터 확인용 정상 쿼리
SELECT SCHEMA_NAME
FROM information_schema.SCHEMATA;

SELECT TABLE_SCHEMA, TABLE_NAME
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'training_db';

SELECT TABLE_SCHEMA, TABLE_NAME, COLUMN_NAME
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'training_db';
```

이러한 메타데이터 접근 권한은 DBMS 및 계정 권한에 따라 달라진다. 데이터베이스 계정에 필요 이상의 권한을 주지 않아야 한다.

### 4.5 안전한 구현 패턴

```python
# Python DB-API의 파라미터 바인딩 개념 예시
cursor.execute(
    "SELECT id FROM users WHERE username = %s AND password_hash = %s",
    (username, password_hash)
)
```

실제 서비스에서는 비밀번호를 평문으로 저장·비교하지 않고, Argon2id·bcrypt 등 적절한 비밀번호 해싱 체계와 검증 라이브러리를 사용한다. 바인딩은 **값**을 안전하게 전달하며, 테이블명·정렬 방향처럼 동적으로 선택하는 식별자는 별도 허용 목록이 필요하다.

## 6. 면접 대비 핵심 Q&A

**Q1. Nmap의 `open`, `closed`, `filtered`는 무엇이 다른가요?**  
A. `open`은 서비스가 수신 중인 상태, `closed`는 접근 가능한 호스트에서 해당 포트를 수신하지 않는 상태, `filtered`는 필터링 등으로 포트 상태를 판단하기 어려운 상태입니다.

**Q2. TCP SYN 스캔과 UDP 스캔의 차이는?**  
A. SYN 스캔은 TCP 응답(SYN/ACK, RST 등)을 활용합니다. UDP는 응답이 없는 경우가 많아 `open|filtered`처럼 모호한 결과가 나올 수 있습니다.

**Q3. SUID는 왜 보안 점검 대상인가요?**  
A. 프로그램이 파일 소유자의 유효 권한으로 실행될 수 있으므로, 취약한 SUID 실행 파일은 권한 상승 통로가 될 수 있기 때문입니다.

**Q4. Metasploit과 Meterpreter는 같은 것인가요?**  
A. Metasploit은 침투 테스트 프레임워크이고, Meterpreter는 그 안에서 사용될 수 있는 고급 페이로드·세션 인터페이스입니다.

**Q5. Idle Scan은 무엇을 이용하나요?**  
A. 제3의 호스트에서 관찰 가능한 IPID 변화 등을 이용해 대상 포트 상태를 간접 추정합니다. 성립 조건이 까다롭습니다.

**Q6. 피싱 방어에서 MFA가 중요한 이유는?**  
A. 비밀번호가 노출되더라도 추가 인증으로 계정 탈취 가능성을 줄일 수 있습니다. 특히 피싱 저항성 인증 방식이 유리합니다.

**Q7. SQL Injection의 근본 원인은?**  
A. 신뢰할 수 없는 입력을 SQL 명령 문자열에 직접 결합해 데이터와 코드의 경계가 무너지는 것입니다.

**Q8. UNION 기반 SQL Injection에서 열 개수가 중요한 이유는?**  
A. UNION으로 결합하는 SELECT 결과는 열 수가 같고 각 열의 자료형이 호환되어야 하기 때문입니다.

**Q9. information_schema는 무엇인가요?**  
A. 데이터베이스·테이블·컬럼 등의 메타데이터를 조회하는 시스템 뷰 집합입니다.

**Q10. SQL Injection의 대표적인 방어책은?**  
A. Prepared Statement와 파라미터 바인딩을 기본으로 사용하고, 최소 권한·오류 관리·입력 검증을 병행합니다.
