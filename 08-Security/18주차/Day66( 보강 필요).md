# 보안 학습 간단 정리 (2026.11.02 ~ 11.04)

> 이번 주 직접 확인한 실습 기록을 바탕으로 작성한 간략 복습 노트입니다. 11월 4일은 결석으로 수업 내용을 확인하지 못했으므로 제외했습니다.

## 1. 11월 2일 (월) — Nmap 및 리눅스 권한

### Nmap 서비스 탐지
- `nmap -sS -sV 192.168.20.200` : TCP SYN 스캔과 서비스/버전 탐지.
- 확인된 주요 포트: 21(FTP), 22(SSH), 23(Telnet), 25(SMTP), 53(DNS), 80(HTTP), 110(POP3), 111(RPC), 143(IMAP), 443(HTTPS), 993(IMAPS), 995(POP3S), 3306(MySQL).
- **핵심:** 포트가 열려 있다는 사실과 실제 취약점이 존재한다는 사실은 다릅니다. 버전 정보는 추가 검증의 단서입니다.

### 리눅스 계정 및 SUID
- `find / -perm -4000 2>/dev/null` : SUID가 설정된 파일 조회.
- `usermod`를 이용한 사용자 로그인 셸 변경 및 `su`를 통한 계정 전환 확인.
- SUID는 실행 파일이 실행되는 동안 파일 소유자의 권한으로 동작하도록 하는 비트입니다.
- **보안 관점:** 불필요한 SUID 파일과 과도한 권한은 점검 대상입니다.

## 2. 11월 3일 (화) — 취약점 진단 및 모의침투 도구

### Nessus / Docker Compose
- Nessus와 테스트용 Linux 컨테이너 환경 구성 시도.
- `Nessus Plugins: License already in use` 오류 발생.
- **상태:** 정상적인 취약점 진단 완료로 기록하지 않음. 추후 강사와 재점검 예정.

### Metasploit / Nmap
- `auxiliary/scanner/portscan/syn` : SYN 기반 포트 스캔 모듈.
- `auxiliary/scanner/smb/smb_version` : SMB 버전 정보 확인 모듈.
- Idle Scan 실습: 좀비 호스트(192.168.20.202)와 대상(192.168.20.200)을 이용한 스캔 및 Wireshark IP Identification(IP ID) 값 관찰.
- **핵심:** Idle Scan은 제3자 호스트의 IP ID 변화 등을 활용하는 간접 스캔 방식이며, 동작 여부는 호스트의 IP ID 특성에 좌우됩니다.

### Meterpreter (격리된 실습 VM)
- Windows 7 가상 환경에서 세션을 획득해 기능을 관찰.
- 화면 확인, 프로세스 목록, 프로세스 이관, 권한 상승 및 파일 작업 등 기능 확인.
- 시작 프로그램 경로를 통한 재실행 동작도 실습에서 관찰.
- **방어 관점:** 최소 권한, 엔드포인트 탐지, 시작 프로그램·프로세스 이상 징후 점검의 중요성 확인.

### Social-Engineer Toolkit (SET)
- Credential Harvester의 웹 템플릿 방식과 HTTP POST 수집 흐름을 실습.
- 테스트 환경에서 폼 데이터가 서버 측 로그에 남는 동작 확인.
- **방어 관점:** 피싱 페이지 식별, URL 검증, MFA 및 자격 증명 보호의 중요성.
- 실습 중 사용한 계정·비밀번호 등 민감한 값은 기록에서 제외.

## 4. 핵심 개념 한눈에 보기

| 주제 | 기억할 핵심 |
|---|---|
| Nmap | 포트·서비스를 식별하지만, 탐지 결과만으로 취약점 확정 불가 |
| SUID | 실행 파일 소유자 권한으로 동작할 수 있어 권한 관리가 중요 |

| Meterpreter | 침투 후 세션에서 다양한 동작을 수행할 수 있는 페이로드 기능 |

## 5. 짧은 면접 복습 Q&A

**Q1. SYN Scan과 서비스 버전 탐지는 무엇이 다른가요?**  
A. SYN Scan은 TCP 포트 상태를 확인하고, 서비스 버전 탐지는 응답을 분석해 실행 중인 서비스와 버전을 추정합니다.

**Q2. SUID가 보안상 중요한 이유는 무엇인가요?**  
A. 특정 실행 파일이 소유자 권한으로 실행될 수 있으므로 잘못된 설정이나 취약점이 권한 상승으로 이어질 수 있기 때문입니다.

**Q3. 취약점 스캐너 결과를 그대로 확정해도 되나요?**  
A. 아닙니다. 오탐 가능성이 있으므로 버전·설정·영향 범위를 추가 검증해야 합니다.

**Q4. 피싱 대응의 핵심은 무엇인가요?**  
A. URL 및 도메인 검증, MFA, 사용자 교육, 의심스러운 로그인 탐지와 신속한 계정 보호 조치입니다.
