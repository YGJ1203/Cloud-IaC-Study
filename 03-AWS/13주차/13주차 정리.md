# 1. 이번 주 핵심 흐름

이번 주의 가장 중요한 흐름은 다음과 같다.

```text
AWS 계정 및 IAM
        ↓
VPC 네트워크 구성
        ↓
Subnet 구성
        ↓
Internet Gateway 연결
        ↓
Route Table 설정
        ↓
Security Group 설정
        ↓
EC2 배포
        ↓
Load Balancer / Auto Scaling
        ↓
S3
        ↓
CloudFormation
        ↓
IaC(Infrastructure as Code)
```

기존 네트워크/Linux/Kubernetes에서 학습했던 개념이 AWS에서는 **클라우드 리소스 형태로 구현된다.**

# 2. AWS 기본 개념

## Region

AWS의 물리적인 서비스 지역.

예:

```text
ap-northeast-2
```

= 서울 리전

하나의 Region 내부에는 여러 Availability Zone이 존재한다.

```text
Region
 ├─ AZ-A
 ├─ AZ-B
 ├─ AZ-C
 └─ AZ-D
```

---

## Availability Zone

하나 이상의 데이터센터로 구성된 독립적인 가용 영역.

여러 AZ에 서버를 분산하면 특정 AZ에 장애가 발생해도 서비스를 계속 운영할 수 있도록 설계할 수 있다.

```text
            Load Balancer
                  │
        ┌─────────┴─────────┐
        │                   │
      AZ-A                AZ-B
        │                   │
      EC2                 EC2
```

핵심 목적:

- 고가용성
- 장애 분산
- 서비스 연속성

# 3. IAM

IAM은 AWS 리소스에 대한 **인증(Authentication)과 권한(Authorization)**을 관리한다.

```text
IAM
 ├─ User
 ├─ Group
 ├─ Role
 └─ Policy
```

## Root User

AWS 계정을 생성한 최상위 계정.

모든 권한을 가지고 있기 때문에 일상적인 관리 작업에는 사용을 최소화하는 것이 좋다.

## IAM User

AWS를 실제로 사용하는 개별 사용자.

필요한 권한만 부여하는 것이 기본 원칙이다.

## Policy

AWS 리소스에 대한 접근 권한을 정의한다.

기본 구조:

```json
{
  "Effect": "Allow",
  "Action": "...",
  "Resource": "..."
}
```

핵심 보안 원칙:

> **Principle of Least Privilege**

사용자에게 필요한 최소한의 권한만 부여한다.

# 4. VPC

VPC(Virtual Private Cloud)는 AWS에서 사용하는 **논리적으로 격리된 가상 네트워크**이다.

실습 구성:

```text
MyVPC01
10.0.0.0/16
```

구조:

```text
AWS
└─ VPC 10.0.0.0/16
     │
     ├─ Public Subnet
     │
     ├─ Route Table
     │
     ├─ Internet Gateway
     │
     ├─ Security Group
     │
     └─ EC2
```

기존 네트워크에서 배웠던

```text
Network
Subnet
Gateway
Routing
ACL
NAT
```

개념이 AWS에서도 그대로 활용된다.

---

# 5. Subnet

VPC의 IP 주소 범위를 더 작은 네트워크로 분할한 것이다.

실습:

```text
VPC
10.0.0.0/16

Public Subnet
10.0.1.0/24
```

즉,

```text
10.0.0.0/16
     ↓
10.0.1.0/24
```

형태로 네트워크를 분리하였다.

---

# 6. Public / Private Subnet

## Public Subnet

인터넷으로 나갈 수 있는 경로가 존재하는 Subnet.

일반적인 조건:

```text
Subnet
   ↓
Route Table
   ↓
0.0.0.0/0
   ↓
Internet Gateway
```

## Private Subnet

Internet Gateway로 직접 연결되는 기본 경로가 없는 Subnet.

일반적으로 다음과 같은 서버를 배치한다.

```text
Database
Application Server
Internal Server
```

인터넷으로 나가는 통신이 필요하다면 NAT Gateway 등을 사용할 수 있다.

---

# 7. Internet Gateway

Internet Gateway(IGW)는 VPC와 인터넷 사이의 통신을 가능하게 하는 AWS 리소스이다.

실습:

```text
MyIGW
```

구조:

```text
Internet
   │
Internet Gateway
   │
  VPC
   │
Subnet
   │
 EC2
```

단, IGW를 VPC에 연결했다고 해서 EC2가 바로 인터넷과 통신할 수 있는 것은 아니다.

**Route Table 설정이 필요하다.**

---

# 8. Route Table

Route Table은 패킷을 어느 방향으로 전달할지 결정한다.

Public Subnet의 대표적인 Route:

```text
Destination       Target

10.0.0.0/16       local
0.0.0.0/0         Internet Gateway
```

의미:

```text
10.0.0.0/16
→ VPC 내부 통신

0.0.0.0/0
→ 나머지 목적지는 Internet Gateway
```

기존 라우터의 Default Route와 연결해서 이해할 수 있다.

```text
ip route 0.0.0.0 0.0.0.0 Gateway
```

AWS에서는:

```text
0.0.0.0/0 → IGW
```

---

# 9. Security Group

Security Group은 EC2 등의 리소스에 적용되는 **가상 방화벽**이다.

이번 실습에서는 다음 트래픽을 허용하였다.

```text
HTTP
HTTPS
SSH
ICMP
```

대표 포트:

```text
HTTP    TCP 80
HTTPS   TCP 443
SSH     TCP 22
```

## 중요한 특징

Security Group은 **Stateful**이다.

예를 들어 inbound에서 SSH 요청이 허용되어 연결이 성립하면 해당 요청에 대한 응답 트래픽은 자동으로 허용된다.

---

# 10. Network ACL과 Security Group

둘 다 트래픽을 제어하지만 적용 위치와 동작 방식이 다르다.

| 구분 | Security Group | Network ACL |
|---|---|---|
| 적용 대상 | ENI/인스턴스 수준 | Subnet |
| 상태 | Stateful | Stateless |
| Allow | 가능 | 가능 |
| Deny | 별도 명시적 Deny 규칙 방식 아님 | 가능 |

기억법:

```text
NACL
→ Subnet 입구

Security Group
→ EC2 앞 경비원
```

---

# 11. EC2

EC2는 AWS에서 제공하는 가상 서버 서비스이다.

기존 VMware의 VM과 상당히 비슷한 개념으로 접근할 수 있다.

```text
VMware VM
   ↕
AWS EC2 Instance
```

EC2 생성 시 주요 설정:

```text
AMI
Instance Type
Key Pair
VPC
Subnet
Security Group
Storage
Public IP
```

---

# 12. AMI

AMI(Amazon Machine Image)는 EC2를 생성할 때 사용하는 서버 이미지이다.

예:

```text
Amazon Linux
Ubuntu
Windows Server
```

VMware 관점에서 생각하면 VM을 만들기 위한 **OS 이미지/템플릿**과 비슷하다.

---

# 13. Key Pair

EC2 접속에 사용하는 인증 수단.

Linux EC2의 경우 일반적으로 SSH 접속에 사용한다.

```text
Client
   │
Private Key
   │
 SSH
   │
 EC2
```

Private Key는 외부에 노출되지 않도록 안전하게 관리해야 한다.

---

# 14. Public IP / Private IP

EC2는 상황에 따라 Private IP와 Public IP를 사용할 수 있다.

```text
EC2
├─ Private IP
└─ Public IP
```

Private IP:

```text
VPC 내부 통신
```

Public IP:

```text
인터넷 통신
```

이번 실습에서도 EC2에 Public/Private IP가 각각 할당되는 것을 직접 확인하였다.

---

# 15. Load Balancer

Load Balancer는 여러 서버로 트래픽을 분산한다.

```text
          Client
             │
             ▼
       Load Balancer
        /     |     \
       /      |      \
     EC2     EC2     EC2
```

장점:

- 부하 분산
- 가용성 향상
- 장애 서버 우회
- Auto Scaling과 연계

Kubernetes에서 사용했던 Service / Ingress / HAProxy 개념과도 연결해서 이해할 수 있다.

---

# 16. Auto Scaling

Auto Scaling은 트래픽이나 정책에 따라 EC2 인스턴스 수를 자동으로 조절한다.

```text
Traffic 증가
      ↓
Auto Scaling
      ↓
EC2 증가
```

반대로 부하가 감소하면:

```text
Traffic 감소
      ↓
EC2 감소
      ↓
비용 절감
```

주요 개념:

```text
Minimum Capacity
Desired Capacity
Maximum Capacity
```

예:

```text
Min     2
Desired 4
Max     6
```

---

# 17. Launch Template

Auto Scaling에서 EC2를 어떤 설정으로 생성할지 정의하는 템플릿이다.

예:

```text
AMI
Instance Type
Key Pair
Security Group
User Data
```

구조:

```text
Launch Template
       ↓
Auto Scaling Group
       ↓
EC2 EC2 EC2 EC2
```

---

# 18. S3

S3(Simple Storage Service)는 AWS의 **Object Storage 서비스**이다.

기본 구조:

```text
S3
└─ Bucket
     ├─ Object
     ├─ Object
     └─ Object
```

일반적인 파일 시스템처럼 디스크 블록을 직접 다루는 것이 아니라 **Object 단위로 데이터를 저장한다.**

활용:

```text
정적 파일
이미지
백업
로그
웹 콘텐츠
데이터 저장
```

---

# 19. S3 핵심 용어

## Bucket

Object를 저장하는 최상위 컨테이너.

## Object

S3에 저장되는 실제 데이터.

Object는 크게 다음으로 구성된다.

```text
Key
Value
Metadata
```

# 20. IaC

IaC는 **Infrastructure as Code**의 약자이다.

인프라를 Console에서 일일이 클릭해서 만드는 대신 코드로 정의하고 배포한다.

기존 방식:

```text
AWS Console
→ VPC 클릭
→ Subnet 클릭
→ IGW 클릭
→ Route Table 클릭
→ Security Group 클릭
→ EC2 클릭
```

IaC:

```text
Template 작성
      ↓
CloudFormation 실행
      ↓
AWS 인프라 자동 생성
```

장점:

```text
자동화
재사용
일관성
버전 관리
빠른 구축
실수 감소
```

---

# 21. CloudFormation

CloudFormation은 AWS에서 제공하는 대표적인 IaC 서비스이다.

YAML 또는 JSON을 사용해 AWS 인프라를 정의할 수 있다.

기본 구조:

```yaml
Parameters:

Resources:

Outputs:
```

---

# 22. Parameters

사용자로부터 값을 입력받을 수 있다.

예:

```yaml
Parameters:
  KeyName:
    Description: EC2 KeyPair
    Type: AWS::EC2::KeyPair::KeyName
```

즉,

```text
CloudFormation 실행
        ↓
KeyName 선택
        ↓
Template 내부에서 사용
```

---

# 23. Resources

실제로 생성할 AWS 리소스를 정의한다.

예:

```yaml
Resources:
  MyVPC04:
    Type: AWS::EC2::VPC
```

여기서:

```text
MyVPC04
→ CloudFormation 내부 논리적 이름

AWS::EC2::VPC
→ 생성할 AWS 리소스 종류
```

---

# 24. VPC CloudFormation 예제

```yaml
Resources:
  MyVPC04:
    Type: AWS::EC2::VPC
    Properties:
      CidrBlock: 10.0.0.0/16
      EnableDnsSupport: 'true'
      EnableDnsHostnames: 'true'
      Tags:
        - Key: Name
          Value: MyVPC04
```

해석:

```text
VPC 생성
↓
CIDR = 10.0.0.0/16
↓
DNS 기능 활성화
↓
DNS Hostname 활성화
↓
Name Tag = MyVPC04
```

---

# 25. Internet Gateway CloudFormation

```yaml
MyIGW:
  Type: AWS::EC2::InternetGateway
  Properties:
    Tags:
      - Key: Name
        Value: MyIGW
```

이 코드는 Internet Gateway 리소스를 생성한다.

하지만 생성만 해서는 VPC에 연결되지 않는다.

따라서 별도의 Attachment 리소스가 필요하다.

개념:

```text
Internet Gateway 생성
          +
VPC 생성
          ↓
VPCGatewayAttachment
          ↓
VPC ↔ IGW 연결
```

---

# 26. CloudFormation 의존 관계

CloudFormation에서는 리소스들이 서로 참조하면서 생성된다.

예:

```text
VPC
 ↓
Subnet
 ↓
EC2
```

Subnet을 생성하려면 VPC가 필요하고,

EC2를 특정 Subnet에 배치하려면 해당 Subnet이 필요하다.

CloudFormation은 이러한 **리소스 간 의존 관계**를 바탕으로 배포 순서를 결정할 수 있다.

---

# 27. Ref

`Ref`는 다른 리소스나 Parameter의 값을 참조할 때 사용한다.

예:

```yaml
VpcId: !Ref MyVPC04
```

의미:

```text
MyVPC04가 생성한 VPC의 ID를 사용
```

예:

```text
vpc-xxxxxxxx
```

를 직접 입력하는 대신 CloudFormation이 값을 연결한다.

---

# 28. GetAtt

`GetAtt`는 리소스의 특정 Attribute 값을 가져올 때 사용한다.

형태:

```yaml
!GetAtt Resource.Attribute
```

예:

```text
EC2
 ├─ InstanceId
 ├─ PrivateIp
 ├─ PublicDnsName
 └─ ...
```

필요한 속성을 다른 리소스나 Output에서 사용할 수 있다.

# 31. 면접 핵심 질문

## Q1. VPC란?

AWS에서 사용자가 정의할 수 있는 논리적으로 격리된 가상 네트워크이다.

---

## Q2. Public Subnet이란?

Internet Gateway로 향하는 경로가 Route Table에 구성되어 있어 인터넷 통신이 가능한 형태로 설계된 Subnet이다.

---

## Q3. Internet Gateway의 역할은?

VPC와 인터넷 간의 통신 경로를 제공한다.

---

## Q4. Security Group과 NACL의 차이는?

Security Group은 ENI/인스턴스 수준에 적용되는 Stateful 보안 기능이고, NACL은 Subnet 수준에 적용되는 Stateless 보안 기능이다.

---

## Q5. Auto Scaling을 사용하는 이유는?

트래픽 변화에 따라 EC2 인스턴스 수를 자동으로 조정하여 가용성과 비용 효율성을 확보하기 위해 사용한다.

---

## Q6. Load Balancer의 역할은?

사용자의 요청을 여러 서버로 분산하여 특정 서버에 부하가 집중되는 것을 방지하고 서비스 가용성을 높인다.

---

## Q7. S3는 어떤 Storage인가?

파일을 Object 단위로 저장하는 Object Storage 서비스이다.

---

## Q8. IaC란?

Infrastructure as Code의 약자로, 인프라 구성을 코드로 정의하고 자동으로 생성 및 관리하는 방식이다.

---

## Q9. CloudFormation이란?

AWS 리소스를 YAML 또는 JSON 템플릿으로 정의하여 자동으로 배포하고 관리할 수 있도록 하는 AWS의 IaC 서비스이다.

---

## Q10. `!Ref`는 무엇인가?

CloudFormation Template에서 Parameter 또는 다른 Resource의 값을 참조할 때 사용한다.

---

# 32. 트러블슈팅 기본 순서 ⭐

EC2 웹 서버가 접속되지 않는다면 무작정 EC2부터 확인하지 않는다.

```text
1. EC2 Running?
        ↓
2. Public IP 존재?
        ↓
3. Security Group 허용?
        ↓
4. Subnet 확인
        ↓
5. Route Table 확인
        ↓
6. 0.0.0.0/0 → IGW 존재?
        ↓
7. IGW가 VPC에 Attach?
        ↓
8. EC2 내부 Web Service 실행?
```

Linux까지 포함하면:

```bash
systemctl status httpd
ss -lntp
curl localhost
```

이후 외부에서:

```text
Client → Public IP → SG → Route → Subnet → EC2
```

흐름을 따라가며 확인한다.

# 33. 비용 관리 체크 ⚠️

AWS 실습에서는 리소스를 생성하는 것뿐 아니라 **사용 후 정리하는 습관**도 중요하다.

특히 확인할 것:

```text
EC2
Load Balancer
NAT Gateway
RDS
Auto Scaling Group
Elastic IP
EBS Volume
```

실습 종료 후 Console에서:

```text
Running Resource가 남아 있는가?
```

를 확인한다.

단순히 EC2만 종료했다고 모든 비용 발생 가능성이 사라지는 것은 아니다.

# 34. 이번 주 가장 중요한 개념 10개

```text
1. VPC = AWS 가상 네트워크

2. Subnet = VPC 네트워크 분할

3. IGW = 인터넷 연결

4. Route Table = 패킷 이동 경로

5. Security Group = Stateful 가상 방화벽

6. EC2 = AWS 가상 서버

7. Load Balancer = 트래픽 분산

8. Auto Scaling = EC2 자동 확장/축소

9. S3 = Object Storage

10. CloudFormation = AWS IaC
```

# 36. ⭐ 이번 주 최종 정리

이번 주부터 AWS를 시작했지만 지금까지 배웠던 내용과 완전히 분리된 분야는 아니다.

```text
Network
   +
Linux
   +
Virtualization
   +
Docker / Kubernetes
   +
YAML
   ↓
AWS Cloud
```

특히 네트워크에서 배웠던

```text
IP
Subnet
Routing
Gateway
NAT
ACL
Load Balancing
```

개념이 AWS의

```text
VPC
Subnet
Route Table
IGW
NAT Gateway
Security Group / NACL
ELB
```

형태로 다시 등장한다.

그리고 Kubernetes에서 YAML을 이용하여 리소스를 선언했던 경험은 CloudFormation의 IaC 방식을 이해하는 데 직접적으로 연결된다.

이번 주의 가장 중요한 변화는 단순히 AWS Console에서 리소스를 만들어본 것이 아니라,

```text
"클라우드 인프라의 구조를 이해하고"

          ↓

"그 구조를 코드로 만들기 시작했다."
```

는 것이다.
