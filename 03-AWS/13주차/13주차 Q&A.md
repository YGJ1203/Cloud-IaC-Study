> **목표:** 명령/콘솔 사용법보다 **“왜 이렇게 구성하는가?”**를 설명할 수 있도록 정리

# 1. AWS 기본 개념

## Q1. AWS란 무엇인가?

AWS는 서버, 네트워크, 스토리지, 데이터베이스 등의 IT 인프라를 인터넷을 통해 필요한 만큼 사용할 수 있도록 제공하는 **클라우드 컴퓨팅 플랫폼**입니다.

물리 서버를 직접 구매하고 구축하지 않아도 필요한 자원을 빠르게 생성하고 확장할 수 있습니다.

### ⭐ 핵심 키워드

- On-Demand
- 확장성(Scalability)
- 탄력성(Elasticity)
- 사용량 기반 과금
- 고가용성

---

# 2. IAM

## Q2. IAM이란?

**IAM(Identity and Access Management)**은 AWS 리소스에 대한 사용자 인증과 권한을 관리하는 서비스입니다.

대표적으로 다음을 관리합니다.

- User
- Group
- Role
- Policy

---

## Q3. Root 계정을 일상적인 관리에 사용하면 안 되는 이유는?

Root 계정은 AWS 계정 전체에 대한 강력한 권한을 가지고 있기 때문에 탈취될 경우 피해 범위가 매우 큽니다.

따라서 Root 계정에는 MFA를 적용하고, 실제 운영에서는 필요한 권한만 부여한 IAM 사용자나 Role을 사용하는 것이 좋습니다.

### ⭐ 핵심

> **최소 권한 원칙(Principle of Least Privilege)**

사용자에게 업무 수행에 필요한 최소한의 권한만 부여합니다.

---

## Q4. IAM User와 IAM Role의 차이는?

IAM User는 일반적으로 특정 사용자나 애플리케이션에 지속적인 AWS 접근 주체를 만드는 개념입니다.

IAM Role은 특정 사용자에게 고정되는 것이 아니라 필요할 때 **임시 권한을 위임받아 사용하는 방식**입니다.

예를 들어 EC2가 S3에 접근해야 한다면 Access Key를 EC2 내부에 저장하기보다는 EC2에 IAM Role을 연결하는 방법이 권장됩니다.

---

# 3. EC2

## Q5. EC2란 무엇인가?

**EC2(Elastic Compute Cloud)**는 AWS에서 제공하는 가상 서버 서비스입니다.

CPU, 메모리, OS, 스토리지 등을 선택하여 필요한 서버를 생성할 수 있습니다.

쉽게 말하면:

> **AWS에서 생성해서 사용하는 VM**

이라고 이해할 수 있습니다.

---

## Q6. AMI란?

**AMI(Amazon Machine Image)**는 EC2 인스턴스를 생성하기 위한 이미지입니다.

운영체제와 일부 소프트웨어 구성 등을 포함할 수 있으며 동일한 환경의 EC2를 반복해서 생성하는 데 사용할 수 있습니다.

---

## Q7. Key Pair는 왜 필요한가?

EC2에 안전하게 접속하기 위한 인증 수단입니다.

Linux EC2에서는 주로 SSH 공개키 인증에 사용됩니다.

```text
Client
   │
   │ SSH
   ▼
EC2
```

비밀번호 인증보다 공개키 기반 인증을 사용함으로써 보안을 강화할 수 있습니다.

---

# 4. VPC

## Q8. VPC란?

**VPC(Virtual Private Cloud)**는 AWS 내부에 사용자가 직접 구성하는 논리적으로 격리된 가상 네트워크입니다.

예:

```text
MyVPC01
10.0.0.0/16
```

VPC 내부에 다음과 같은 네트워크 리소스를 구성할 수 있습니다.

- Subnet
- Route Table
- Internet Gateway
- NAT Gateway
- Security Group
- EC2

---

## Q9. VPC를 `/16`으로 만들고 Subnet을 `/24`로 나누는 이유는?

큰 주소 공간을 VPC에 확보하고 목적별로 작은 네트워크로 분리하여 관리하기 위해서입니다.

예:

```text
VPC
10.0.0.0/16
│
├── Public Subnet
│   10.0.1.0/24
│
├── Public Subnet
│   10.0.2.0/24
│
├── Private Subnet
│   10.0.11.0/24
│
└── Private Subnet
    10.0.12.0/24
```

이렇게 구성하면 웹 서버, WAS, DB 등의 역할에 따라 네트워크를 분리할 수 있습니다.

---

# 5. Public / Private Subnet

## Q10. Public Subnet과 Private Subnet의 차이는?

핵심은 단순히 Public IP의 존재 여부가 아니라 **라우팅 구성**입니다.

### Public Subnet

라우팅 테이블에 Internet Gateway를 향하는 기본 경로가 존재합니다.

```text
0.0.0.0/0 → IGW
```

### Private Subnet

Internet Gateway로 직접 향하는 기본 경로가 없습니다.

외부로 나가는 인터넷 연결이 필요하다면 일반적으로 NAT Gateway 등을 사용합니다.

```text
Private EC2
    │
    ▼
NAT Gateway
    │
    ▼
Internet Gateway
    │
    ▼
Internet
```

---

# 6. Internet Gateway

## Q11. Internet Gateway란?

VPC와 인터넷 사이의 통신을 가능하게 하는 VPC 구성 요소입니다.

하지만 IGW를 VPC에 연결했다고 해서 EC2가 자동으로 인터넷 통신이 가능한 것은 아닙니다.

---

## ☠️ Q12. IGW를 연결했는데 EC2에서 인터넷이 안 됩니다. 무엇을 확인해야 하나요?

다음 항목을 확인하겠습니다.

1. IGW가 VPC에 정상적으로 연결되어 있는지
2. Subnet Route Table에 기본 경로가 있는지

```text
0.0.0.0/0 → IGW
```

3. EC2에 Public IPv4 또는 적절한 공인 주소가 있는지
4. Security Group 설정
5. Network ACL 설정
6. EC2 내부 OS 방화벽 및 서비스 상태

### ⭐ 면접 포인트

> 하나만 보고 판단하지 않고 **네트워크 경로 전체를 단계적으로 확인한다.**

---

# 7. Route Table

## Q13. Route Table이란?

네트워크 트래픽을 어느 방향으로 전달할지 결정하는 라우팅 규칙입니다.

예:

```text
Destination       Target

10.0.0.0/16       local
0.0.0.0/0         igw-xxxxx
```

`local` 경로는 VPC 내부 통신에 사용됩니다.

`0.0.0.0/0 → IGW`는 목적지를 특정하지 못한 외부 트래픽을 Internet Gateway 방향으로 전달합니다.

---

# 8. Security Group

## Q14. Security Group이란?

EC2 등의 리소스에 적용되는 **상태 기반(Stateful) 가상 방화벽**입니다.

Inbound와 Outbound 규칙을 통해 허용할 트래픽을 제어합니다.

예:

```text
SSH     TCP 22
HTTP    TCP 80
HTTPS   TCP 443
ICMP
```

---

## Q15. Security Group과 NACL의 차이는?

| 구분 | Security Group | NACL |
|---|---|---|
| 적용 대상 | ENI/인스턴스 수준 | Subnet 수준 |
| 방식 | Stateful | Stateless |
| Allow | O | O |
| Deny 규칙 | X | O |
| 규칙 처리 | 전체 규칙 평가 | 번호 순서에 따라 평가 |

### ⭐ 면접 핵심

> **SG = Stateful / NACL = Stateless**

---

# 9. NAT Gateway

## Q16. NAT Gateway는 왜 사용하는가?

Private Subnet의 인스턴스가 인터넷에서 직접 접근받지 않으면서도 외부 인터넷으로 통신할 수 있도록 하기 위해 사용합니다.

예:

```text
Internet
   ▲
   │
  IGW
   ▲
   │
NAT Gateway
(Public Subnet)
   ▲
   │
Private EC2
```

대표적인 사용 사례는 Private EC2의 패키지 업데이트나 외부 API 접근 등입니다.

---

## ☠️ Q17. NAT Gateway는 Private Subnet에 배치하나요?

일반적인 Public NAT Gateway 구성에서는 **Public Subnet에 배치합니다.**

NAT Gateway가 인터넷으로 트래픽을 전달하려면 Public Subnet의 Route Table을 통해 IGW에 접근할 수 있어야 하기 때문입니다.

Private Subnet에서는 다음과 같이 설정합니다.

```text
0.0.0.0/0 → NAT Gateway
```

# 10. S3

## Q18. S3란?

**Amazon S3(Simple Storage Service)**는 AWS의 객체 스토리지 서비스입니다.

파일을 객체 형태로 Bucket에 저장합니다.

```text
Bucket
│
├── image.jpg
├── index.html
└── backup.zip
```

대표적인 용도:

- 이미지 및 파일 저장
- 백업
- 로그 저장
- 정적 콘텐츠
- 데이터 저장소

---

## Q19. EC2의 디스크와 S3는 같은 스토리지인가요?

아닙니다.

EC2에서 일반적인 디스크처럼 사용하는 EBS는 **Block Storage**이고 S3는 **Object Storage**입니다.

```text
EBS
→ Block Storage
→ EC2 Disk 용도

S3
→ Object Storage
→ Object/File 저장
```

---

# 11. Load Balancer

## Q20. Load Balancer를 사용하는 이유는?

클라이언트 요청을 여러 서버로 분산하여 하나의 서버에 트래픽이 집중되는 것을 방지하고 서비스 가용성과 확장성을 높이기 위해 사용합니다.

```text
        Client
           │
           ▼
     Load Balancer
       /        \
      ▼          ▼
    EC2-1      EC2-2
```

---

# 12. Auto Scaling

## Q21. Auto Scaling이란?

서비스 부하나 정책에 따라 EC2 인스턴스 수를 자동으로 증가시키거나 감소시키는 기능입니다.

예:

```text
트래픽 증가
   ↓
EC2 추가
   ↓
트래픽 감소
   ↓
EC2 감소
```

이를 통해 서비스 가용성을 유지하면서 불필요한 리소스 비용을 줄일 수 있습니다.

---

## Q22. Auto Scaling과 Load Balancer를 같이 사용하는 이유는?

Auto Scaling은 **서버 수를 조절**하고 Load Balancer는 **요청을 여러 서버로 분산**합니다.

따라서 함께 사용하면 다음과 같은 구조를 만들 수 있습니다.

```text
             Internet
                │
                ▼
         Load Balancer
          /    │    \
         ▼     ▼     ▼
       EC2    EC2    EC2
         ▲           ▲
         └───────────┘
          Auto Scaling
```

즉,

> **ELB = 트래픽 분산**  
> **Auto Scaling = 서버 수 조절**

입니다.

# 13. CloudFormation

## Q23. CloudFormation이란?

AWS 인프라를 코드로 정의하고 자동으로 생성 및 관리할 수 있도록 해주는 **IaC(Infrastructure as Code)** 서비스입니다.

예를 들어 다음 리소스를 코드로 정의할 수 있습니다.

```text
VPC
Subnet
IGW
Route Table
Security Group
EC2
```

콘솔에서 하나씩 생성하지 않고 YAML 또는 JSON 템플릿으로 인프라를 재현할 수 있습니다.

---

## Q24. CloudFormation의 장점은?

대표적인 장점은 다음과 같습니다.

- 인프라 자동화
- 동일 환경 재현
- 구성 표준화
- 변경 관리
- 반복 작업 감소
- 코드 리뷰 및 버전 관리와 결합 가능

따라서 사람이 콘솔에서 직접 작업하면서 발생할 수 있는 실수를 줄일 수 있습니다.

---

# 14. CloudFormation 주요 구성

## Q25. `Parameters`란?

템플릿 실행 시 외부에서 값을 입력받기 위해 사용합니다.

예:

```yaml
Parameters:
  KeyName:
    Type: AWS::EC2::KeyPair::KeyName
```

템플릿 내부에 특정 값을 고정하지 않고 재사용성을 높일 수 있습니다.

---

## Q26. `Resources`란?

CloudFormation이 실제로 생성하고 관리할 AWS 리소스를 정의하는 핵심 영역입니다.

```yaml
Resources:
  MyVPC:
    Type: AWS::EC2::VPC
```

### ⭐ 매우 중요

> CloudFormation 템플릿에서 `Resources`는 핵심 필수 영역이다.

---

## Q27. `Ref`는 무엇인가?

다른 Parameter 또는 Resource의 값을 참조할 때 사용하는 CloudFormation 내장 함수입니다.

예:

```yaml
VpcId: !Ref MyVPC
```

리소스 ID를 직접 하드코딩하지 않고 다른 리소스와 연결할 수 있습니다.

---

# 15. ☠️ 실무 상황형 문제

## Q28. 웹 서버를 인터넷에 공개해야 합니다. 어떤 AWS 리소스가 필요할까요?

하나의 기본적인 예를 들면 다음과 같습니다.

```text
VPC
 │
 ├── Public Subnet
 │       │
 │      EC2
 │       │
 │   Security Group
 │
 ├── Route Table
 │      0.0.0.0/0
 │          │
 │         IGW
 │          │
 └──────── Internet
```

필요한 요소:

- VPC
- Public Subnet
- Internet Gateway
- Route Table
- Public IPv4
- Security Group
- EC2

---

## Q29. DB 서버를 인터넷에서 직접 접근하지 못하게 하려면?

DB 서버를 Private Subnet에 배치하고 인터넷으로 직접 연결되는 경로를 구성하지 않습니다.

```text
Internet
   │
   ▼
Load Balancer
   │
   ▼
Web / App
   │
   ▼
Private DB
```

Security Group도 DB 포트를 인터넷 전체에 공개하지 않고 필요한 애플리케이션 계층에서만 접근할 수 있도록 제한합니다.

# 16. ☠️☠️ 압박 꼬리질문

## Q30. Security Group에서 22번 포트를 `0.0.0.0/0`으로 열어도 되나요?

기술적으로 가능하지만 보안상 권장되지 않습니다.

SSH가 필요하다면 관리자 IP 등 필요한 출발지로 제한하는 것이 좋습니다.

```text
Bad

SSH 22
Source: 0.0.0.0/0
```

```text
Better

SSH 22
Source: 관리자 IP/32
```

---

## Q31. EC2가 Private Subnet에 있는데 패키지를 다운로드해야 합니다. 어떻게 하겠습니까?

Private Subnet의 기본 경로를 Public Subnet에 위치한 NAT Gateway로 설정하여 외부 인터넷으로 나갈 수 있도록 구성할 수 있습니다.

```text
Private EC2
     │
     ▼
Private Route Table
0.0.0.0/0 → NAT GW
     │
     ▼
NAT Gateway
     │
     ▼
IGW
     │
     ▼
Internet
```

---

## Q32. CloudFormation을 쓰면 모든 문제를 자동으로 해결해 주나요?

아닙니다.

CloudFormation은 정의한 인프라를 자동으로 생성하고 관리하는 도구이기 때문에 잘못된 설계를 코드로 작성하면 **잘못된 인프라 역시 자동으로 생성될 수 있습니다.**

따라서 네트워크, 보안, IAM 및 AWS 리소스에 대한 기본 이해가 중요합니다.

# 17. 🔥 30초 면접 답변

## Q. VPC 구성을 간단히 설명해 주세요.

> VPC는 AWS에서 사용하는 논리적으로 격리된 가상 네트워크입니다. VPC 내부를 Public과 Private Subnet으로 분리하고, Public Subnet은 Internet Gateway로 외부와 통신할 수 있도록 구성합니다. Private Subnet의 서버가 외부 인터넷 접근이 필요한 경우 NAT Gateway 등을 사용할 수 있습니다. Route Table을 통해 트래픽 경로를 제어하고 Security Group과 NACL을 이용해 접근을 제한합니다.

# 18. 🔥 장애 대응 답변

## Q. 웹 서버에 접속할 수 없다면 어떻게 확인하시겠습니까?

무작정 EC2를 재시작하기보다 네트워크 흐름을 기준으로 확인합니다.

```text
① EC2 상태
      ↓
② Web Service 상태
      ↓
③ Public IP / DNS
      ↓
④ Security Group
      ↓
⑤ NACL
      ↓
⑥ Route Table
      ↓
⑦ Internet Gateway
```

Linux 서버라면 추가로 다음과 같은 항목도 확인할 수 있습니다.

```bash
systemctl status httpd
ss -lntp
curl localhost
ip addr
ip route
```

### ⭐ 면접에서 중요한 사고방식

> **증상 → 계층별 확인 → 원인 범위 축소 → 해결 → 재검증**

AWS 1주차에서 가장 중요한 것은 서비스 이름을 많이 외우는 것이 아닙니다.
