## 4. ICMP Flood

```bash
hping3 --interface eth0 --icmp 192.168.20.200 --flood --rand-source
```

Kali 송신: 113,830패킷
CentOS Wireshark: 총 95패킷 캡처(요청/응답 등 포함)

Sophos:
id=2104
name="ICMP flood detected"
action="ICMP flood"
fwrule=60014
initf=eth0
dstip=192.168.20.200
proto=1 type=8

탐지 시각: 18:22:59, 18:25:24~25 부근
역방향 ICMP Echo Reply(type=0) 로그도 확인.

결과: ICMP Flood 탐지 성공.

## 5. UDP Flood

초기 인터페이스 선택 오류를 수정해 eth0로 재실행.

```bash
hping3 --interface eth0 --udp -p 53 192.168.20.200 --flood --rand-source
```

Kali 송신: 120,450패킷
CentOS Wireshark: 총 27패킷 캡처

Sophos:
id=2105
name="UDP flood detected"
action="UDP flood"
fwrule=60013
initf=eth0
dstip=192.168.20.200
proto=17 dstport=53

탐지 시각: 18:40:55~56 부근.
UDP/53 패킷은 Wireshark에서 DNS 또는 malformed DNS로 표시될 수 있지만 정상 DNS 질의를 의미하지는 않는다.

결과: UDP Flood 탐지 성공.

## 6. TCP SYN Flood

```bash
hping3 -I eth0 --syn -p 80 192.168.20.200 --flood --rand-source
```

Kali 송신: 134,636패킷
CentOS Wireshark: 마지막 패킷 번호 149까지 확인(응답 등 포함)

Sophos 로그:
2026:11:23-18:48:50
id="2103"
name="SYN flood detected"
action="SYN flood"
fwrule="60012"
initf="eth0"
srcmac="00:0c:29:b0:67:b0"
dstmac="00:0c:29:df:6c:37"
srcip="99.127.83.243"
dstip="192.168.20.200"
proto="6"
dstport="80"
tcpflags="SYN"

- proto=6: TCP
- tcpflags=SYN: TCP 연결 시작
- initf=eth0: Sophos WAN 유입
- dstport=80: CentOS 웹 포트
- 무작위 srcip는 --rand-source에 의한 위조 주소
- 동일한 srcmac은 Kali eth0 MAC과 일치

결과: SYN Flood 탐지 성공.

## 8. WebAdmin 로그인 장애

증상:
- SYN 실습 이후 WebAdmin 로그인 실패
- Sophos root 콘솔 접속은 가능
- 당시 uptime load average 약 0.04/0.04/0.05

로그 확인:
```bash
grep -iE 'login|failed|invalid|locked|admin' /var/log/aua.log | tail -n 30
```

확인 로그:
[WARN-070] Too many failed logins
id="3005"
name="Authentication failed"
srcip="192.168.20.1"
user="admin"
caller="webadmin"
reason="Too many failures from client 192.168.20.1, still blocked for 596 ..."

분석:
- 관리자 PC 192.168.20.1의 반복 로그인 실패로 클라이언트 IP가 일시적으로 인증 제한됨.
- 일부 root 계정 시도 로그도 존재.
- 추가 시도를 중단하고 잠금 시간 경과 후 정상 로그인 성공.
- 정상 로그인 후 SYN Flood 탐지 로그 확보.

## 9. 관리자 접속 SYN도 Flood 탐지

2026:11:23-18:53:26
id="2103"
name="SYN flood detected"
initf="eth1"
srcip="192.168.20.1"
dstip="192.168.20.100"
proto="6"
dstport="4444"
tcpflags="SYN"

유사 이벤트: 18:53:26, 18:53:52, 19:06:58.

확인된 사실: 관리자 PC→WebAdmin SYN 패킷이 Flood로 탐지되었다.
미확인: 이 이벤트가 실제 TCP 연결을 차단했는지, 인증 실패 누적과 직접 연결됐는지.
이후 WebAdmin 정상 로그인은 확인됨.

## 10. 패킷 수 해석 주의

| 유형 | Kali 송신 | CentOS 캡처 |
|---|---:|---:|
| ICMP | 113,830 | 총 95 |
| UDP | 120,450 | 총 27 |
| SYN | 134,636 | 마지막 번호 149 |

송신 수 - 캡처 수 = 방화벽 차단 수로 계산할 수 없다.
캡처 구간, 필터, 패킷 손실, 응답 포함 여부, IP 위조 및 다른 정책의 영향을 구분해야 한다.
hping3 --flood의 응답 손실 역시 Drop의 직접 증거가 아니다.

향후 격리된 실습망에서 낮은 전송률·짧은 시간으로 Sophos WAN/LAN 및 CentOS 캡처와 정책 Drop 카운터를 비교하면 차단 효과를 더 엄밀히 검증할 수 있다.

## 12. 보고서용 요약

Kali Linux–Sophos UTM–CentOS로 구성된 격리된 VMware 환경에서 라우팅 경로를 검증하고 ICMP, UDP, TCP SYN Flood 테스트를 수행하였다. Sophos UTM에서 세 유형의 Flood 탐지 로그(ID 2104, 2105, 2103)를 모두 확인했으며, GEOIP 정책에 의한 패킷 Drop 로그도 별도로 확보하였다. WebAdmin 로그인 장애는 인증 실패 누적에 따른 클라이언트 IP의 일시적 제한으로 확인되었고, 이후 정상 로그인에 성공하였다. 관리자 접속 SYN 패킷도 Flood로 탐지되었지만 실제 연결 차단 및 인증 장애와의 인과관계는 추가 검증이 필요하다.

## 13. 면접 Q&A

Q. SYN Flood란?
A. 대량의 TCP SYN 요청으로 서버의 연결 상태 관리에 부담을 줄 수 있는 DoS 공격이다.

Q. --rand-source란?
A. 패킷의 출발지 IP를 무작위로 위조하는 옵션이다.

Q. Flood 탐지 로그는 차단 성공의 증거인가?
A. 탐지 증거는 되지만 실제 차단 여부와 수량은 별도 Drop 로그 및 패킷 계측으로 검증해야 한다.

Q. WebAdmin 로그인 장애의 직접 확인된 원인은?
A. 클라이언트 192.168.20.1에서 로그인 실패가 누적되어 일시적 인증 제한이 적용된 것이다.

Q. SYN Flood 탐지와 인증 잠금은 같은가?
A. 아니다. 네트워크 트래픽 탐지와 인증 보호는 서로 다른 메커니즘이다.
