## 2. 네트워크 구성

### 2.1 주요 장비 IP 주소

| 장비 | 인터페이스 | IP 주소 | 역할 |
|---|---|---|---|
| VMware NAT Gateway | VMnet8 | 192.168.2.254 | 외부 네트워크 게이트웨이 |
| FortiGate | port1 | 192.168.2.100/24 | 외부망 |
| FortiGate | port2 | 192.168.20.100/24 | 내부망 |
| Kali Linux | eth0 | 192.168.2.50/24 | 외부망 실습 |
| Kali Linux | eth1 | 192.168.20.50/24 | 내부망 실습 |
| Snort IDS | eth0 | 192.168.20.101/24 | 침입 탐지 |
| CentOS | eth0 | 192.168.20.200/24 | 내부 서버 |
| Windows Server 2008 | - | 192.168.20.201 | 실습 대상 |
| Windows 7 | - | 192.168.20.202 | 실습 대상 |

### 2.2 네트워크 구조

```text
               외부 인터넷
                    |
          VMware NAT Gateway
             192.168.2.254
                    |
             VMnet8 (NAT)
                    |
        FortiGate NGFW - port1
             192.168.2.100
                    |
             [FortiGate]
                    |
        FortiGate NGFW - port2
            192.168.20.100
                    |
          VMnet1 (Host-Only)
                    |
       +------------+-------------+
       |            |             |
     Snort        CentOS        Kali eth1
  20.101         20.200         20.50
```

**참고 사항**

- 기존 Gateway VM은 FortiGate와 IP가 중복되므로 종료한 상태로 진행하였다.
- Kali Linux는 외부망과 내부망에 모두 연결되어 있다.
- Kali에서 내부 서버로 직접 통신할 경우 FortiGate를 우회할 수 있으므로, 이후 방화벽 차단 실습에서는 실제 통신 경로를 확인해야 한다.
- Snort는 내부망에 연결되어 있으나, 다른 장비 사이의 모든 유니캐스트 패킷을 자동으로 수집하는 것은 아니다.

## 3. FortiGate NGFW 네트워크 설정

### 3.1 인터페이스 IP 설정

```text
config system interface
    edit "port1"
        set mode static
        set ip 192.168.2.100 255.255.255.0
        set allowaccess http https ping ssh
    next
    edit "port2"
        set mode static
        set ip 192.168.20.100 255.255.255.0
        set allowaccess http https ping ssh
    next
end
```

설정 확인:

```text
show system interface port1
show system interface port2
get system interface physical
```

**설정 내용**

- port1: 외부망 연결
- port2: 내부망 연결
- HTTP/HTTPS: 관리 페이지 접근
- Ping: ICMP 연결 확인
- SSH: 원격 CLI 관리

**실습 결과:** 인터페이스 설정 후 FortiGate 관리 페이지 접근 확인.

> HTTP 관리 접근은 실습용으로 허용하였으며, 실제 운영 환경에서는 HTTPS 중심의 관리 접근 제한이 필요하다.

### 3.2 DNS 서버 설정

```text
config system dns
    set primary 8.8.8.8
    set secondary 8.8.4.4
end
```

설정 확인:

```text
show system dns
get system dns
```

- Primary DNS: 8.8.8.8
- Secondary DNS: 8.8.4.4

### 3.3 기본 게이트웨이 설정

```text
config router static
    edit 1
        set gateway 192.168.2.254
        set device "port1"
    next
end
```

설정 확인:

```text
show router static
get router info routing-table all
```

**설정 목적**

FortiGate가 외부 네트워크로 패킷을 전달할 때 VMware NAT Gateway를 사용하도록 기본 경로를 구성한다.

### 3.4 FortiGate Ping 테스트

```text
execute ping 8.8.8.8
execute ping www.google.com
execute ping update.fortiguard.net

execute ping 192.168.2.50
execute ping 192.168.20.200
execute ping 192.168.20.201
execute ping 192.168.20.202
```

**검증 결과**

- 외부 인터넷 통신 정상
- Kali Linux 통신 정상
- CentOS 통신 정상
- Windows Server 2008 및 Windows 7은 VM 미실행으로 응답 없음

Windows VM의 Ping 실패는 이번 실습에서 방화벽 차단의 증거가 아니다.

## 4. FortiGate NAT 정책 설정

### 4.1 NAT 정책 구성

```text
config firewall policy
    edit 1
        set name "MyNAT"
        set srcintf "port2"
        set dstintf "port1"
        set action accept
        set srcaddr "all"
        set dstaddr "all"
        set schedule "always"
        set service "ALL"
        set nat enable
    next
end
```

설정 확인:

```text
show firewall policy
```

### 4.2 NAT 정책 분석

| 설정 | 의미 |
|---|---|
| srcintf port2 | 내부망 출발 |
| dstintf port1 | 외부망 목적 |
| action accept | 트래픽 허용 |
| srcaddr all | 모든 출발지 주소 |
| dstaddr all | 모든 목적지 주소 |
| schedule always | 항상 적용 |
| service ALL | 모든 서비스 허용 |
| nat enable | 출발지 NAT 활성화 |

**정리**

FortiGate의 내부망에서 외부망으로 향하는 트래픽을 허용하고, 출발지 NAT를 적용하도록 설정하였다.

현재 정책은 초기 연결 검증용으로 허용 범위가 넓다. 추후 보안 진단에서는 출발지, 목적지, 서비스 범위를 제한하는 방향을 검토할 수 있다.

## 5. CentOS 외부 통신 검증

### 5.1 라우팅 테이블 확인

실행 명령어:

```bash
ip route
```

실제 결과:

```text
192.168.20.0/24 dev eth0 proto kernel scope link src 192.168.20.200
169.254.0.0/16 dev eth0 scope link
default via 192.168.20.100 dev eth0
```

**분석**

- CentOS IP: 192.168.20.200
- 기본 게이트웨이: 192.168.20.100
- 기본 게이트웨이가 FortiGate port2로 지정되어 있음

### 5.2 외부 Ping 테스트

실행 명령어:

```bash
ping -c 4 8.8.8.8
```

실제 결과:

```text
4 packets transmitted, 4 received, 0% packet loss

rtt min/avg/max/mdev =
34.150/36.376/40.470/2.464 ms
```

### 5.3 검증 결과

| 항목 | 결과 |
|---|---|
| 전송 패킷 | 4 |
| 수신 패킷 | 4 |
| 패킷 손실률 | 0% |
| 평균 RTT | 36.376 ms |
| 외부 통신 | 성공 |

**결론**

CentOS의 기본 게이트웨이가 FortiGate로 지정되어 있으며, 외부 IP에 대한 ICMP 통신이 정상적으로 이루어졌다.

다만 NAT 정책에 실제 매칭된 세션 및 트래픽 로그는 아직 별도로 확인하지 않았다.

## 7. Snort 설정 파일 검증

### 7.1 테스트 명령어

```bash
snort -T -c /etc/snort/snort.conf -i eth0
```

### 7.2 실제 출력

```text
pcap DAQ configured to passive.
Acquiring network traffic from "eth0".

--== Initialization Complete ==--

Snort successfully validated the configuration!
Snort exiting
```

### 7.3 결과 분석

| 항목 | 결과 |
|---|---|
| 설정 파일 검사 | 성공 |
| 탐지 엔진 초기화 | 성공 |
| 규칙 로딩 검사 | 성공 |
| 패킷 수집 인터페이스 | eth0 |
| DAQ 모드 | Passive |

**Passive 모드란?**

Snort가 네트워크 패킷을 수집하고 분석하여 의심스러운 트래픽에 대한 경고를 생성하는 방식이다.

- IDS: 침입 탐지 및 경고
- IPS: 침입 탐지 및 차단

현재 Snort는 IDS 방식으로 사용한다.

**주의:** 설정 검증 성공은 실제 공격 탐지 성공과 다르다.


결과:

```text

```

**판단**

local.rules 파일은 존재하지만, 검색 결과 활성화된 `alert` 규칙은 확인되지 않았다.

### 9.2 ICMP 탐지 규칙 작성 안내

기존 파일 백업:

```bash
cp -a /etc/snort/rules/local.rules /etc/snort/rules/local.rules.bak
```

파일 편집:

```bash
vi /etc/snort/rules/local.rules
```

추가할 탐지 규칙:

```text
alert icmp 192.168.20.200 any -> 192.168.20.101 any (msg:"KAIST ICMP Echo Request Detected"; itype:8; sid:3001001; rev:1;)
```

### 9.3 탐지 규칙 해석

| 구성 | 의미 |
|---|---|
| alert | 경고 생성 |
| icmp | ICMP 패킷 검사 |
| 192.168.20.200 | CentOS |
| 192.168.20.101 | Snort |
| itype:8 | Echo Request |
| sid:3001001 | 사용자 정의 규칙 ID |
| rev:1 | 규칙 버전 |

**진행 상태**

- 규칙 작성 방법 안내 완료
- 실제 파일 추가 여부 미확인
- Snort 설정 재검증 미확인
- Alert 로그 생성 미확인

## 10. 오늘의 핵심 개념

### 10.1 FortiGate NGFW

- 네트워크 간 트래픽을 정책에 따라 허용하거나 차단하는 보안 장비
- 라우팅 및 NAT 기능 제공
- 보안 정책과 로그를 이용해 접근 통제 효과 검증 가능

### 10.2 Snort IDS

- 네트워크 패킷 분석
- 시그니처 기반 탐지 규칙 사용
- 의심스러운 트래픽에 대한 Alert 생성
- Passive IDS 모드에서는 직접 패킷을 차단하지 않음

### 10.3 NAT

내부 IP 주소를 외부 통신에 적합한 주소로 변환하는 기술이다.

이번 실습에서는 FortiGate의 출발지 NAT를 설정하였다.

### 10.4 ICMP

- Echo Request: Type 8
- Echo Reply: Type 0
- Ping 명령어에서 네트워크 연결 상태 확인에 사용

### 10.5 tcpdump와 Snort의 차이

| 도구 | 역할 |
|---|---|
| tcpdump | 네트워크 패킷 수집 및 출력 |
| Snort | 패킷을 탐지 규칙과 비교하고 경고 생성 |

따라서 tcpdump에서 패킷이 보인다고 Snort 탐지가 성공한 것은 아니다.
