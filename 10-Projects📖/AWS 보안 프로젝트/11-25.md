### 3.2 2페이지 - FortiGate 공격 전 보안 로그 확인

**설명 문구**

공격 수행 전 FortiGate 보안 이벤트 및 Anomaly 로그를 확인한다.

조회된 이상 트래픽 탐지 이벤트가 없음을 확인한다.

**증빙 화면**

- FortiGate 보안 이벤트 요약
- Anomaly 로그 조회
- 조회 결과 없음

**학습 포인트**

공격 전 로그 상태를 확인하면 공격 이후 발생한 탐지 이벤트와 비교할 수 있다.

단, 로그가 없다는 사실만으로 네트워크에 이상 트래픽이 전혀 존재하지 않았다고 단정할 수는 없다.

### 3.3 3페이지 - Kali Linux Flood 공격 수행

**설명 문구**

Kali Linux의 hping3를 이용하여 CentOS 서버(192.168.20.200)를 대상으로 ICMP, TCP SYN, UDP Flood 공격을 수행한다.

각 공격의 패킷 전송 결과를 확인한다.

**실습 명령어 기록**

ICMP Flood:

```bash
hping3 --interface eth0 --icmp 192.168.20.200 --flood --rand-source
```

TCP SYN Flood:

```bash
hping3 --interface eth0 --syn -p 80 192.168.20.200 --flood --rand-source
```

UDP Flood:

```bash
hping3 --interface eth0 --udp -p 53 192.168.20.200 --flood --rand-source
```

**확보한 전송 기록**

| 공격 유형 | 전송 패킷 |
|---|---:|
| ICMP Flood | 155,452 |
| TCP SYN Flood | 208,618 |
| UDP Flood | 184,170 |

**주의사항**

위 명령어는 허가된 격리 실습 환경에서 수행한 기록이다.

`--flood`는 높은 전송률을 발생시키며, `--rand-source`는 출발지 IP를 위조한다.

해당 명령어 실행 결과에 표시되는 100% Packet Loss는 방화벽의 100% 차단률을 의미하지 않는다.

---

### 3.4 4페이지 - ICMP Flood 공격 탐지 및 대응 확인

**설명 문구**

ICMP Flood 공격 수행 후 FortiGate Anomaly 로그에서 icmp_flood 탐지 및 clear_session 동작을 확인한다.

CentOS Wireshark에서 ICMP 패킷이 표시되지 않았으며, CPU 및 메모리 사용률에 뚜렷한 변화가 없음을 확인한다.

**로그 증빙**

- Attack Name: icmp_flood
- Severity: Critical
- Action: clear_session
- Log Count: 850

**Wireshark 증빙**

- Display Filter: icmp
- 공격 테스트 시점의 패킷 미표시 화면 확보

**시스템 상태**

- CPU 사용률: 약 0%
- 메모리 사용률: 약 33.3%

**해석 시 주의사항**

Wireshark에 패킷이 표시되지 않은 결과는 방화벽의 트래픽 제한 가능성을 뒷받침한다.

그러나 이것만으로 전체 공격 패킷이 완전히 차단됐다고 확정할 수는 없다.

---

### 3.5 5페이지 - TCP SYN Flood 공격 탐지 및 대응 확인

**설명 문구**

TCP SYN Flood 공격 수행 후 FortiGate Anomaly 로그에서 tcp_syn_flood 탐지 및 clear_session 동작을 확인한다.

CentOS의 시스템 자원 상태를 확인하고, Wireshark에서 관찰된 일반 관리 통신과 공격 트래픽을 구분한다.

**로그 증빙**

- Attack Name: tcp_syn_flood
- Severity: Critical
- Action: clear_session
- Log Count: 134,067

**Wireshark 증빙**

- Display Filter: tcp
- 일반 TCP/HTTPS 관리 통신 관찰

**시스템 상태**

- CPU 사용률: 약 0%
- 메모리 사용률: 약 33.3%

**주의사항**

Wireshark 화면에 표시된 192.168.20.100과 192.168.20.1 간의 통신은 공격 대상 CentOS로 향하는 TCP SYN Flood 트래픽과 구분해야 한다.

따라서 해당 화면은 TCP 트래픽 관찰 자료로 활용하고, SYN Flood 탐지의 핵심 증빙은 FortiGate Anomaly 로그를 사용한다.

### 3.7 7페이지 - FortiGate 정상 통신 검증

**설명 문구**

Kali Linux에서 CentOS 서버로 Ping을 수행한 결과, 패킷 4개가 모두 정상적으로 응답하였다.

Wireshark에서 ICMP Echo Request 및 Echo Reply를 확인하여 정상 통신이 유지됨을 검증한다.

**실습 명령어**

```bash
ping -c 4 192.168.20.200
```

**결과**

```text
4 packets transmitted
4 received
0% packet loss
```

**Wireshark 결과**

- ICMP Echo Request 확인
- ICMP Echo Reply 확인
- Kali Linux와 CentOS 간 정상 통신 확인

**학습 포인트**

FortiGate DoS Policy가 적용되어 있더라도 정상적인 ICMP 통신은 가능하다.

따라서 공격 탐지 결과뿐 아니라 정상 통신 검증도 함께 수행하는 것이 중요하다.

## 5. CLI 증빙 ① - DoS Policy 설정 확인

### 5.1 명령어

FortiGate CLI:

```bash
show firewall dos-policy
```

### 5.2 확인할 설정

- 정책 인터페이스
- 출발지 및 목적지 주소
- 탐지 항목 활성화 여부
- 차단 동작
- 임계값
- 로그 활성화 여부

**주요 확인 항목 예시**

```text
set interface "port1"
set srcaddr "all"
set dstaddr "KAIST-CentOS"
```

TCP SYN Flood:

```text
set name "tcp_syn_flood"
set status enable
set log enable
set action block
set threshold 1000
```

UDP Flood:

```text
set name "udp_flood"
set status enable
set log enable
set action block
set threshold 1000
```

ICMP Flood:

```text
set name "icmp_flood"
set status enable
set log enable
set action block
set threshold 150
```

※ 위 내용은 확인 대상 설정의 예시이며, 실제 장비 출력 결과와 대조해야 한다.

## 6. CLI 증빙 ② - 정상 ICMP 패킷 흐름 확인

### 6.1 검증 목적

FortiGate 외부 인터페이스(port1)와 내부 인터페이스(port2)에서 정상 ICMP 패킷의 전달 여부를 확인한다.

### 6.2 외부 인터페이스 캡처

FortiGate CLI:

```bash
diagnose sniffer packet port1 'icmp and dst host 192.168.20.200' 4 20
```

Kali Linux:

```bash
ping -c 4 192.168.20.200
```

확인할 내용:

- Kali Linux 출발지 IP
- CentOS 목적지 IP
- ICMP Echo Request
- port1 유입 패킷

### 6.3 내부 인터페이스 캡처

FortiGate CLI:

```bash
diagnose sniffer packet port2 'icmp and dst host 192.168.20.200' 4 20
```

Kali Linux:

```bash
ping -c 4 192.168.20.200
```

확인할 내용:

- ICMP Echo Request
- port2 전달 패킷
- 목적지 CentOS IP

### 6.4 통합 패킷 캡처

필요한 경우 다음 명령어로 양쪽 인터페이스의 패킷을 함께 관찰할 수 있다.

```bash
diagnose sniffer packet any 'icmp and dst host 192.168.20.200' 4 100
```

예상되는 정상 패킷 흐름:

```text

    |
```

## 9. PPT 작성 시 주의사항

### 9.1 탐지 로그와 실제 차단 패킷 수 구분

FortiGate 로그의 `count` 또는 `repeats` 값은 실제 폐기된 패킷 수와 동일하다고 단정할 수 없다.

따라서 다음과 같이 작성한다.

**권장 표현**

- Flood 공격 탐지 확인
- Anomaly 로그 발생 확인
- clear_session 동작 확인
- 공격 시점의 패킷 관찰 결과 확인

**피해야 할 표현**

- 공격 패킷 100% 차단 완료
- 134,067개 공격 패킷 완전 차단
- CPU 사용률 0%이므로 모든 공격 차단 성공

### 9.2 Wireshark 결과 해석

Wireshark에서 특정 프로토콜의 패킷이 표시되지 않은 경우, 캡처 인터페이스와 필터 및 시점을 함께 고려해야 한다.

특히 TCP SYN Flood 페이지에 표시된 관리 통신은 공격 패킷과 구분하여 설명한다.

### 9.3 보고서 문체 통일

기존 UTM PPT와 유사하게 다음 형식을 유지한다.

```text
설정한다.
확인한다.
수행한다.
검증한다.
```

설명은 페이지당 약 두 문장으로 구성하여 사진 중심의 레이아웃을 유지한다.

## 10. 오늘의 핵심 Q&A

### Q1. GUI 설정 화면이 있는데 CLI 캡처도 필요한가?

필수는 아니지만 설정값을 교차 검증하는 자료로 활용할 수 있다.

### Q2. DoS Policy CLI에서 가장 중요한 항목은?

탐지 유형, 활성화 상태, 차단 동작, 임계값 및 로그 설정이다.

### Q3. port1과 port2에서 ICMP 패킷을 확인하는 이유는?

정상 패킷이 FortiGate에 유입되고 내부 서버 방향으로 전달되는지 확인하기 위해서이다.

### Q4. 정상 Ping이 성공하면 DoS Policy가 동작하지 않는 것인가?

아니다.

정상 트래픽은 허용되면서 비정상적인 Flood 트래픽은 탐지될 수 있다.

### Q5. CLI 캡처를 추가하면 PPT 페이지를 늘려야 하는가?

반드시 그렇지는 않다.

기존 1페이지와 7페이지에 통합할 수 있으며, 화면 가독성이 떨어진다면 기존 GUI 증빙만 유지해도 된다.

### Q6. FortiGate Anomaly 로그의 clear_session은 무엇인가?

FortiGate가 관련 세션을 정리하는 대응 동작이다.

이 로그만으로 전체 공격 패킷의 완전 차단을 확정할 수는 없다.
