## 1. AWS 클라우드 보안 진단

### ① Security Group (SG)
- EC2 등 AWS 리소스의 네트워크 접근을 제어하는 가상 방화벽
- Stateful 방식
- 허용(Allow) 규칙만 설정 가능
- 인바운드와 아웃바운드 규칙을 별도로 관리
- 응답 트래픽은 별도 허용 규칙 없이 통과 가능

**핵심:** SG는 인스턴스 및 리소스 수준의 접근 제어에 사용한다.

### ② Network ACL (NACL)
- VPC 서브넷 단위로 트래픽 제어
- Stateless 방식
- Allow 및 Deny 규칙 설정 가능
- 인바운드와 아웃바운드 규칙을 각각 확인해야 함
- 규칙 번호가 낮은 것부터 평가

**핵심:** NACL은 서브넷 단위의 네트워크 접근 제어에 사용한다.

### ③ ALB 및 Target Group
- ALB는 HTTP/HTTPS 요청을 대상 서버로 분산
- Target Group은 요청을 전달할 대상들의 집합
- Health Check를 통해 대상의 응답 상태 확인
- Healthy는 설정된 상태 검사에 정상적으로 응답한다는 의미

**주의:** Healthy 상태가 서버 전체의 보안이나 모든 기능의 정상 동작을 보장하지는 않는다.

### ④ AWS 보안 진단
이번 주에는 AWS 콘솔 설정과 기존 증빙 자료를 기반으로 보안 진단 PPT를 정리했다.

주요 점검 항목:
- 보안 그룹 접근 제어
- NACL 인바운드/아웃바운드 규칙
- 네트워크 및 리소스 구성
- 계정 및 운영 관리 설정
- 실제 설정 화면과 PPT 설명의 일치 여부

**핵심:** 보안 진단은 설정 확인뿐 아니라 근거 자료와 점검 결과를 명확하게 제시하는 과정이다.

## 2. FortiGate와 네트워크 방화벽

### ① FortiGate
- Fortinet의 차세대 방화벽(NGFW)
- 네트워크 트래픽 제어
- 방화벽 정책 기반 접근 통제
- NAT 및 보안 기능 제공
- 허용/차단 로그 분석 가능

### ② 방화벽 정책
일반적으로 다음 요소를 기준으로 트래픽을 제어한다.

- 출발지 인터페이스
- 목적지 인터페이스
- 출발지 주소
- 목적지 주소
- 서비스 및 포트
- 허용 또는 차단 동작

### ③ Stateful 방화벽
- 세션 상태를 추적
- 정상적인 요청에 대한 응답 트래픽을 식별
- 단순 패킷 필터링보다 연결 상태를 고려한 제어 가능

**핵심:** 방화벽 정책은 트래픽이 어디서 어디로 이동하는지 이해한 뒤 설정해야 한다.

## 3. Snort IDS

### ① Snort 개념
- 네트워크 침입 탐지 시스템(IDS)
- 패킷을 분석하고 정의된 규칙과 비교
- 의심스러운 트래픽 발견 시 경고 및 로그 생성

### ② Snort Rule 기본 구조

```snort
alert tcp any any -> any 80 (msg:"HTTP Detection"; sid:1000001; rev:1;)
```

- `alert`: 탐지 시 경고
- `tcp`: 검사 프로토콜
- `any any`: 출발지 IP 및 포트
- `->`: 트래픽 방향
- `any 80`: 목적지 IP 및 포트
- `msg`: 경고 메시지
- `sid`: 규칙 식별 번호
- `rev`: 규칙 버전

### ③ IDS와 IPS 차이
| 구분 | IDS | IPS |
|---|---|---|
| 목적 | 침입 탐지 | 침입 탐지 및 차단 |
| 주요 동작 | 경고 및 기록 | 경고 및 차단 |
| 배치 | 주로 미러링/수동 감시 | 주로 인라인 |

**핵심:** Snort는 설정과 운영 방식에 따라 IDS 또는 IPS로 활용할 수 있다.

## 4. tcpdump 패킷 분석

### ① tcpdump 개념
- CLI 기반 패킷 캡처 및 분석 도구
- 네트워크 인터페이스에서 패킷 관찰
- 프로토콜 및 IP 주소를 기준으로 필터링 가능

### ② 주요 명령어

```bash
tcpdump -nni eth0
```
- `-nn`: IP 주소와 포트 번호를 숫자로 표시
- `-i eth0`: eth0 인터페이스 선택

```bash
tcpdump -nni eth0 icmp
```
- ICMP 패킷 확인

```bash
tcpdump -nni eth0 'icmp and src host 192.168.20.200'
```
- 특정 출발지의 ICMP 패킷 확인

```bash
tcpdump -nni eth0 'tcp port 80'
```
- TCP 80번 포트 트래픽 확인

### ③ ICMP Echo
- Echo Request: Type 8
- Echo Reply: Type 0
- ping 통신 확인에 사용
- 패킷의 출발지와 목적지를 통해 통신 흐름 분석

**실습 핵심:** 패킷이 캡처되었다는 사실과 실제 통신이 성공했다는 사실은 구분해야 한다.

## 7. 이번 주 반드시 기억할 5가지

**① SG와 NACL의 가장 큰 차이**
- SG: Stateful
- NACL: Stateless

**② IDS와 IPS의 차이**
- IDS: 탐지 중심
- IPS: 탐지 및 차단

**③ tcpdump의 목적**
- 패킷을 직접 관찰하여 통신 흐름과 이상 현상을 분석한다.

**④ 방화벽 정책의 핵심**

**⑤ 보안 진단의 핵심**
- 설정 → 검증 → 증빙 → 결과 정리
