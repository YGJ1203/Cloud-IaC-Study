## 1. 실습 개요

### 실습 목적

1. TCP SYN 패킷 생성 및 분석
2. UDP 패킷 생성 및 분석
3. ICMP Echo 패킷 생성 및 분석
4. ICMP LAND 형태의 IP 스푸핑 패킷 분석
5. Snort IDS 및 FortiGate NGFW 방어 검증을 위한 사전 준비

> 이번 실습은 제한된 패킷 수를 전송하는 기초 검증이다.
> 실제 Flood 공격에 의한 서비스 장애나 보안 솔루션의 차단 효과는 아직 검증하지 않았다.

## 3. 사전 점검 - 정상 TCP 통신

### CentOS 명령어

```bash
ip addr show eth0
ss -lnt
tcpdump -ni eth0 'tcp port 80'
```

### Kali 명령어

```bash
curl -I --max-time 5 http://192.168.20.200/
```

### 확인 결과

- CentOS eth0: 192.168.20.200/24
- TCP 80번 포트 LISTEN 확인
- TCP 3-Way Handshake 정상 수행
- Apache HTTP 응답 확인

```text
HTTP/1.1 403 Forbidden
Server: Apache/2.2.3 (CentOS)
```

### 분석

403 Forbidden은 HTTP 접근 거부를 의미한다.

TCP 연결 자체는 정상적으로 이루어졌으며,
SYN → SYN-ACK → ACK 과정이 tcpdump에서 확인되었다.

## 4. TCP SYN 패킷 실습

### Kali 명령어

```bash
hping3 -S -p 80 -c 20 -i u100000 192.168.20.200
```

### CentOS 명령어

```bash
tcpdump -ni eth0 'tcp dst port 80 and tcp[tcpflags] & tcp-syn != 0'
```

### 옵션 설명

| 옵션 | 의미 |
|---|---|
| -S | TCP SYN 플래그 설정 |
| -p 80 | 목적지 TCP 80번 포트 |
| -c 20 | 패킷 20개 전송 |
| -i u100000 | 패킷 간격 0.1초 |

### 결과

```text
20 packets transmitted
20 packets received
0% packet loss
```

CentOS:

```text
20 packets captured
20 packets received by filter
0 packets dropped by kernel
```

### 분석

- SYN 패킷 20개 전송
- CentOS에서 SYN 패킷 20개 확인
- SYN-ACK 응답 20개 확인
- TCP SYN 패킷 생성 및 수신 검증 성공

※ 실제 SYN Flood로 인한 서비스 장애는 확인되지 않음.

---

## 5. UDP 패킷 실습

### Kali 명령어

```bash
hping3 --udp -p 9999 -c 20 -i u100000 192.168.20.200
```

### CentOS 명령어

```bash
tcpdump -nni eth0 'udp and src host 192.168.20.50'
```

### 결과

```text
20 packets transmitted
7 packets received
65% packet loss
```

CentOS에서는 목적지 UDP 9999번 패킷 20개를 확인하였다.

### ICMP 오류 응답

```text
ICMP Port Unreachable from ip=192.168.20.200
```

### 분석

- UDP 패킷 20개 전송
- CentOS에서 UDP 패킷 20개 수집
- UDP 9999번 포트에 수신 서비스가 없어 ICMP 오류 응답 발생
- Kali에서 ICMP 오류 응답 7개 확인

65% packet loss는 hping3 기준 응답 미수신 비율이다.

CentOS에서 UDP 패킷 65%가 유실되었다는 의미는 아니다.

※ 실제 UDP Flood에 의한 서비스 장애는 확인되지 않음.

## 6. ICMP 패킷 실습

### Kali 명령어

```bash
hping3 --icmp -c 20 -i u100000 192.168.20.200
```

### CentOS 명령어

```bash
tcpdump -nni eth0 'icmp and src host 192.168.20.50'
```

### 결과

```text
20 packets transmitted
20 packets received
0% packet loss

round-trip min/avg/max = 1.1/5.6/11.0 ms
```

CentOS:

```text
20 packets captured
20 packets received by filter
0 packets dropped by kernel
```

### 분석

- ICMP Echo Request 20개 전송
- CentOS에서 Echo Request 20개 수집
- Kali에서 Echo Reply 20개 수신
- 평균 RTT 5.6ms
- ICMP 요청 및 응답 정상 확인

※ 실제 ICMP Flood에 의한 서버 부하는 검증하지 않음.

## 7. ICMP LAND 실습

### 개념

ICMP LAND는 출발지 IP 주소를 목적지 IP 주소와 동일하게
위조하여 패킷을 전송하는 방식이다.

### Kali 명령어

```bash
hping3 --icmp -a 192.168.20.200 -c 5 -i u200000 192.168.20.200
```

### CentOS 명령어

```bash
tcpdump -nni eth0 'icmp and src host 192.168.20.200 and dst host 192.168.20.200'
```

### 결과

```text
192.168.20.200 > 192.168.20.200:
ICMP echo request

5 packets captured
5 packets received by filter
0 packets dropped by kernel
```

Kali:

```text
5 packets transmitted
0 packets received
100% packet loss
```

### 분석

- Kali에서 ICMP 패킷 5개 생성
- 출발지 IP를 CentOS IP로 위조
- CentOS에서 위조 패킷 5개 확인
- 출발지와 목적지 IP가 동일하게 표시됨

100% packet loss는 Kali에서 응답을 받지 못했다는 의미이다.

CentOS에서는 위조 패킷 5개가 실제로 수집되었으므로
IP 스푸핑 패킷의 전달 및 수신은 확인되었다.

※ 실제 LAND 공격에 의한 서비스 장애는 검증하지 않음.
