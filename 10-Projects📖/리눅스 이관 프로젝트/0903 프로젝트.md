## 1. 구축 개요

  항목          설정
  ------------- ------------------------------
  OS            CentOS Stream 9
  Hostname      `web-dns`
  Server IP     `10.1.101.200`
  Web Server    Apache HTTP Server (`httpd`)
  VirtualHost   **Port-based VirtualHost**
  DNS           `www.kaist.com`
  Firewall      `firewalld`

  학과              VLAN   Port DocumentRoot
  --------------- ------ ------ -----------------
  AI 컴퓨팅학과       11   8081 `/var/www/www1`
  AI 시스템학과       12   8082 `/var/www/www2`
  AI 미래학과         13   8083 `/var/www/www3`

> VLAN은 학과별 서비스 구분 정보이며, 웹 페이지는 **TCP 목적지 포트**에
> 따라 Apache VirtualHost가 구분한다.

## 4. Apache 설치 및 활성화

웹 서비스를 위해 설치한 핵심 패키지는 `httpd`이다.


-   `status`: 서비스 상태 확인

## 7. Port-based VirtualHost

이번 프로젝트는 **Host-based가 아닌 Port-based VirtualHost**를 사용한다.

``` apache
<VirtualHost *:8081>
    DocumentRoot "/var/www/www1"
</VirtualHost>

<VirtualHost *:8082>
    DocumentRoot "/var/www/www2"
</VirtualHost>

<VirtualHost *:8083>
    DocumentRoot "/var/www/www3"
</VirtualHost>
```

``` text
TCP 8081 → /var/www/www1
TCP 8082 → /var/www/www2
TCP 8083 → /var/www/www3
```

## 9. firewalld 구성

Web + DNS 서버에서 사용하는 주요 서비스/포트:

  서비스   Port
  -------- ------------
  HTTP     TCP 80
  HTTPS    TCP 443
  DNS      TCP/UDP 53
  MySQL    TCP 3306
  www1     TCP 8081
  www2     TCP 8082
  www3     TCP 8083

``` bash
firewall-cmd --permanent --add-port=8081/tcp
firewall-cmd --permanent --add-port=8082/tcp
firewall-cmd --permanent --add-port=8083/tcp
firewall-cmd --reload
firewall-cmd --list-all
```

### Rich Rule을 사용하지 않은 이유

초기에는 Source VLAN별 접근 제한도 검토했으나, 요구사항은 **학과별
페이지를 포트로 분리하여 제공하는 것**이지 VLAN별 접근을 제한하는 것이
아니었다.

따라서 불필요한 Source 제한 없이 TCP 8081\~8083을 허용했다.

> 서비스 분리는 Apache VirtualHost가, 통신 허용은 firewalld가 담당한다.

## 10. DNS 연동

``` text
www.kaist.com
      ↓ DNS
10.1.101.200
```

Client의 DNS Server도 `10.1.101.200`으로 설정한다.

``` text
nslookup www.kaist.com
```

DNS는 **이름 → IP 주소**를 처리한다. `8081` 같은 TCP Port는 DNS가
결정하지 않는다.

``` text
www.kaist.com:8081
       ↓
DNS: www.kaist.com → 10.1.101.200
       ↓
TCP Destination Port 8081
       ↓
Apache VirtualHost *:8081
       ↓
/var/www/www1/index.html
```

## 13. NAT/PAT과 Web Server

내부 Client가 내부 Web Server `10.1.101.200`에 접근할 때 NAT는 필요하지
않다.

Gateway에는 별도로 Dynamic PAT와 Web Server Static PAT가 구성되어 있음을
확인했다.

``` cisco
ip nat inside source list 10 interface Ethernet0/0 overload
access-list 10 permit 10.1.0.0 0.0.255.255
```

Static PAT:

``` text
192.168.2.241:80  → 10.1.101.200:80
192.168.2.241:443 → 10.1.101.200:443
```

> NAT/PAT은 Gateway의 기능이므로 Web Server 자체의 구축 절차와 분리해서
> 이해한다.

## 14. Troubleshooting

### 14.1 DocumentRoot does not exist

증상:

``` text
AH00112: Warning: DocumentRoot [/var/www/www1] does not exist
AH00112: Warning: DocumentRoot [/var/www/www2] does not exist
AH00112: Warning: DocumentRoot [/var/www/www3] does not exist
Syntax OK
```

원인: VirtualHost에는 경로를 지정했지만 실제 디렉터리를 생성하지 않았다.

해결:

``` bash
mkdir -p /var/www/www{1..3}
```

**핵심:** Apache 설정에 경로를 작성하는 것과 실제 파일시스템에 해당
경로가 존재하는 것은 별개다.

### 14.2 Client VLAN / IP Subnet 불일치

초기에는 User1/User2 주소를 VLAN 11/12 기준으로 설정했지만 실제
토폴로지에서 Client는 VLAN 21/22에 속했다.

``` text
User1 → VLAN 21 → 10.1.21.0/24 → GW 10.1.21.254
User2 → VLAN 22 → 10.1.22.0/24 → GW 10.1.22.254
```

``` text
Client IP Subnet
       ↕
Switch Access VLAN
       ↕
Gateway Subinterface / HSRP VIP
```

세 요소가 일치해야 정상 통신한다.

### 14.3 Rich Rule 설계 재검토

요구사항을 다시 확인한 결과 VLAN별 접근 제한이 필요하지 않아 Rich Rule
대신 단순 Port 허용으로 변경했다.

**교훈:** 설정을 복잡하게 만드는 것보다 요구사항에 필요한 수준으로
정확하게 구성하는 것이 중요하다.

## 17. 핵심 개념

-   **Apache (`httpd`)**: HTTP 요청을 받아 웹 콘텐츠를 제공하는 Web
    Server.
-   **DocumentRoot**: 특정 웹 서비스가 제공할 파일의 기준 디렉터리.
-   **Port-based VirtualHost**: 동일 서버에서 서로 다른 TCP Port로 여러
    사이트를 구분하는 방식.
-   **DNS**: Domain Name을 IP Address로 변환. TCP Port는 결정하지
    않는다.
-   **firewalld**: 서버로 들어오는 서비스/포트의 통신 허용 여부를 제어.
-   **`/en/`**: 별도의 VirtualHost가 아니라 DocumentRoot 내부의 URL
    Path.

## 18. 구축 결과

하나의 CentOS Stream 9 서버에서 Apache의 **Port-based VirtualHost**를
이용하여 세 개의 독립적인 학과 홈페이지를 제공하도록 구축하였다.

``` text
TCP 8081 → AI Computing
TCP 8082 → AI Systems
TCP 8083 → AI Futures
```

각 서비스는 한국어 `/`와 영문 `/en/` 페이지를 제공하며, DNS를 통해
`www.kaist.com`을 `10.1.101.200`으로 해석한다. firewalld에서 필요한 웹
포트를 허용하고 Windows Client에서 실제 접속을 검증하여 Web Server
구축을 완료하였다.
