## 0. 이번 주 핵심 한 장 요약

이번 주 학습의 핵심은 다음 한 문장으로 정리할 수 있다.

> **Linux Server에서 서비스를 실행하고, Client가 네트워크를 통해 해당 서비스에 접근할 수 있도록 DNS와 방화벽까지 함께 구성한다.**

```text
Client
  │
  ├─ DNS 질의 ──────────────> DNS Server (BIND)
  │                            │
  │ <──────── IP 주소 응답 ────┘
  │
  └─ TCP/UDP 연결
       │
       ▼
+---------------- Linux Server ----------------+
|                                              |
|  iptables / firewalld                        |
|           │                                  |
|           ▼                                  |
|      허용된 Service/Port                     |
|           │                                  |
|   +-------+---------+---------+               |
|   │       │         │         │               |
|  HTTP    FTP       SMTP      NFS/Samba       |
|   │                                          |
| Apache(httpd) → Tomcat → JSP → MariaDB       |
|                                              |
+----------------------------------------------+
```

### 반드시 연결해서 기억할 것

1. **서비스가 실행 중이어도 방화벽이 막으면 접속할 수 없다.**
2. **방화벽을 열어도 서비스가 LISTEN 중이 아니면 접속할 수 없다.**
3. **도메인을 사용한다면 DNS가 정상이어야 서비스 서버의 IP를 찾을 수 있다.**
4. **Web/WAS/DB는 서로 다른 계층이며 역할도 다르다.**
5. **FTP는 제어 연결뿐 아니라 데이터 연결, 특히 Passive Port 범위까지 고려해야 한다.**

# Part 1. Linux Network Service의 기본 구조

## 1. 서비스 점검의 기본 순서

서버 접속이 되지 않을 때 무작정 설정 파일부터 수정하지 않는다.

```bash
# 1. IP 주소 확인

# 2. 라우팅 확인

# 3. 상대방 통신 확인
ping <IP>

# 4. 서비스 상태 확인

# 5. LISTEN Port 확인
ss -lntup

# 6. 방화벽 확인
firewall-cmd --list-all

# 7. 필요하면 로그 확인
journalctl -u <service>
```

### 핵심 사고방식

```text
Network → Process → Port → Firewall → Application 설정
```

즉, 장애가 발생하면 **아래 계층부터 위로 올라가며 확인**한다.

# Part 2. NFS와 Samba

## 2. NFS(Network File System)

NFS는 Linux/Unix 계열 시스템에서 네트워크를 통해 디렉터리를 공유할 때 주로 사용하는 서비스다.

### 구조

```text
Server1                              Client1
/test/share1  <--------------------> /mnt/nfs1
/test/share2  <--------------------> /mnt/nfs2
```

서버가 디렉터리를 **export**하고 클라이언트가 해당 디렉터리를 **mount**한다.

### 주요 구성 요소

- `nfs-server` : NFS 서비스
- `rpcbind` : RPC 서비스와 Port 정보를 연결
- `/etc/exports` : 공유 디렉터리 설정
- `exportfs` : export 설정 적용/확인
- `mount` : Client에서 원격 공유 연결

### 예시

```text
192.168.2.203:/test/share1  /mnt/nfs1  nfs  rw  0 0
192.168.2.203:/test/share2  /mnt/nfs2  nfs  ro  0 0
```

`/etc/fstab`에 등록하면 부팅 후에도 자동 마운트할 수 있다.

### `rw`와 `ro`

| 옵션 | 의미 |
|---|---|
| `rw` | 읽기/쓰기 허용 |
| `ro` | 읽기 전용 |

> 서버의 export 옵션과 클라이언트 mount 옵션뿐 아니라 **Linux 파일 권한/소유권도 실제 쓰기 가능 여부에 영향을 준다.**

---

## 3. Samba

Samba는 SMB/CIFS 프로토콜을 이용하여 Linux와 Windows 사이에서도 파일을 공유할 수 있게 한다.

### NFS vs Samba

| 구분 | NFS | Samba |
|---|---|---|
| 대표 환경 | Linux/Unix | Windows ↔ Linux |
| 프로토콜 | NFS | SMB/CIFS |
| 주요 목적 | Unix 계열 파일 공유 | Windows 호환 파일 공유 |

# Part 3. HTTPD / Tomcat / JSP / MariaDB

## 4. Apache HTTP Server (`httpd`)

Apache HTTP Server는 대표적인 Web Server다.

### 기본 역할

```text
Browser → HTTP Request → Apache(httpd) → HTML 등의 정적 콘텐츠 응답
```

### 주요 명령어

```bash
systemctl start httpd
systemctl enable httpd
systemctl status httpd

ss -lntp | grep ':80'
```

기본 HTTP Port는 **TCP 80**, HTTPS는 **TCP 443**이다.

---

## 5. Tomcat — WAS

Tomcat은 Java Servlet/JSP를 실행할 수 있는 Web Application Server(WAS)다.

기본적으로 많이 사용하는 Port:

```text
TCP 8080
```

### Web Server와 WAS 차이

```text
Client
   │
   ▼
Apache HTTPD          ← 정적 콘텐츠 / HTTP 요청 처리
   │
   ▼
Tomcat                ← Java/JSP 등의 동적 처리
   │
   ▼
MariaDB               ← 데이터 저장/조회
```

---

## 6. JSP → MariaDB 연결

실습에서 JSP가 JDBC를 통해 MariaDB에 연결하는 구조를 확인했다.

```java
String DB_URL = "jdbc:mariadb://localhost:3306/testdb";
String DB_USER = "example";
String DB_PASSWORD = "centos";
```

### 의미

```text
jdbc:mariadb://localhost:3306/testdb
                 │        │      │
                 │        │      └─ Database 이름
                 │        └──────── MariaDB Port
                 └───────────────── DB Server
```

`localhost`이므로 JSP/Tomcat과 MariaDB가 같은 서버에서 동작하는 구성이다.

### JDBC 처리 흐름

```text
JSP
 │
 ├─ JDBC Driver Load
 │
 ├─ DB Connection
 │
 ├─ SQL 실행
 │
 ├─ ResultSet 반환
 │
 └─ 결과를 HTML로 출력
```

대표 코드 흐름:

```java
Class.forName("org.mariadb.jdbc.Driver");
conn = DriverManager.getConnection(DB_URL, DB_USER, DB_PASSWORD);
stmt = conn.createStatement();
rs = stmt.executeQuery("select * from users");
```

### MariaDB 기본 Port

```text
TCP 3306
```

DB를 외부 서버에서 접근해야 할 경우 DB 자체의 listen/bind 설정, 사용자 Host 권한, Linux 방화벽 등을 함께 확인해야 한다.

# Part 4. DNS — BIND

## 7. DNS의 역할

DNS는 사람이 사용하는 도메인 이름을 IP 주소와 연결한다.

```text
www.example7777.com
        │
        ▼
      DNS
        │
        ▼
192.168.x.x
```

Linux에서는 대표적으로 **BIND(named)**를 사용한다.

---

## 8. Forward Zone / Reverse Zone

### Forward Lookup

```text
Domain Name → IP Address
```

주로 `A` Record를 사용한다.

### Reverse Lookup

```text
IP Address → Domain Name
```

주로 `PTR` Record를 사용한다.

---

## 9. 주요 DNS Record

| Record | 역할 |
|---|---|
| SOA | Zone의 기본 관리 정보 |
| NS | 해당 Zone의 Name Server |
| A | Hostname → IPv4 |
| PTR | IP → Hostname |
| MX | Mail Server 지정 |

### MX가 중요한 이유

예를 들어 사용자가 다음 주소로 메일을 보낸다고 가정한다.

```text
user@example7777.com
```

송신 Mail Server는 DNS의 MX Record를 조회하여 `example7777.com`의 메일을 어느 Mail Server로 전달해야 하는지 확인할 수 있다.

즉,

```text
DNS MX Record ≠ Mail 전송 자체
```

MX는 **메일 서버의 위치를 알려주는 DNS 정보**이며, 실제 메일 전송은 SMTP가 담당한다.

# Part 5. Mail Server

## 10. SMTP / POP3

### SMTP

메일을 **보내거나 Mail Server 사이에서 전달**하는 데 사용한다.

대표 Port:

```text
TCP 25
```

### POP3

Mail Server에 저장된 메일을 Client가 가져오는 데 사용한다.

대표 Port:

```text
TCP 110
```

### 흐름

```text
Sender
  │
  │ SMTP
  ▼
Mail Server
  │
  │ SMTP
  ▼
Receiver Mail Server
  │
  │ POP3
  ▼
Receiver Client
```

> 실무에서는 SMTP Submission(587), TLS, IMAP 등의 구성이 흔하지만 수업 실습에서는 각 프로토콜의 기본 구조와 Port를 먼저 이해하는 것이 핵심이다.

# Part 6. iptables

## 11. iptables란?

iptables는 Linux Kernel의 Netfilter 기능을 제어하여 패킷을 필터링하는 전통적인 방화벽 관리 도구다.

### 대표 Chain

| Chain | 의미 |
|---|---|
| INPUT | 서버 자신에게 들어오는 패킷 |
| OUTPUT | 서버 자신이 내보내는 패킷 |
| FORWARD | 서버를 통과하여 다른 곳으로 전달되는 패킷 |

### 대표 Target

| Target | 의미 |
|---|---|
| ACCEPT | 허용 |
| DROP | 폐기 |
| REJECT | 거부 응답 후 차단 |

---

## 12. 기본 규칙 형태

```bash
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

분해하면:

```text
iptables
  -A INPUT       INPUT Chain 뒤에 Rule 추가
  -p tcp         TCP Protocol
  --dport 22     목적지 Port 22
  -j ACCEPT      허용
```

---

## 13. Stateful Firewall

Stateful Firewall은 패킷 하나만 독립적으로 보는 것이 아니라 **연결 상태**까지 추적한다.

대표 상태 개념:

- `NEW` : 새로운 연결
- `ESTABLISHED` : 이미 성립된 연결
- `RELATED` : 기존 연결과 관련된 새로운 연결
- `INVALID` : 정상 상태로 판단하기 어려운 패킷

예시 개념:

```text
Client → Server : NEW
Client ↔ Server : ESTABLISHED
```

Stateful 정책을 사용하면 이미 허용되어 정상적으로 성립한 통신의 응답 트래픽을 효율적으로 처리할 수 있다.

# Part 7. firewalld

## 14. firewalld란?

firewalld는 Linux에서 방화벽 정책을 보다 편리하게 관리하기 위한 도구다.

CentOS Stream 9 환경에서는 일반적으로 firewalld를 중심으로 방화벽을 관리한다.

### 상태 확인

```bash
systemctl status firewalld
firewall-cmd --state
```

### 현재 설정 확인

```bash
firewall-cmd --list-all
```

---

## 15. Service 허용

```bash
firewall-cmd --permanent --add-service=ssh
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
```

설정 적용:

```bash
firewall-cmd --reload
```

### 수업에서 다룬 대표 서비스

- Telnet
- SSH
- FTP
- NFS
- RPC-Bind
- Samba
- HTTP
- HTTPS
- MySQL/MariaDB 관련 접근
- DNS
- DHCP
- NTP

```bash

```

# Part 8. FTP와 Passive Port

## 17. FTP가 방화벽에서 까다로운 이유

FTP는 하나의 TCP 연결만 사용하는 단순한 프로토콜이 아니다.

### Control Connection

```text
Client → Server TCP 21
```

로그인, 명령 전달 등에 사용한다.

### Data Connection

파일 목록 조회나 실제 파일 전송에는 별도의 데이터 연결이 필요하다.

Passive Mode에서는 서버가 지정된 높은 Port 범위에서 Client의 데이터 연결을 기다린다.

수업 예시:

```text
50000-51000/tcp
```

따라서 vsftpd에 Passive 범위를 지정했다면 방화벽에서도 **동일한 범위**를 허용해야 한다.

```text
vsftpd Passive Range : 50000-51000
Firewall Open Range  : 50000-51000/tcp
```

두 값이 다르면 로그인은 되는데 디렉터리 목록이나 파일 전송에서 문제가 발생할 수 있다.

# Part 9. iptables vs firewalld

## 18. 두 방식 비교

| 구분 | iptables | firewalld |
|---|---|---|
| 관점 | Rule 중심 | Zone/Service 중심 |
| 사용 난이도 | 상대적으로 직접적/세밀함 | 관리가 편리함 |
| Port 허용 | Rule 직접 작성 | `--add-port` |
| Service 허용 | Port/Protocol 직접 지정 | `--add-service` |
| 상태 확인 | `iptables -L` 등 | `firewall-cmd --list-all` |

### 핵심

둘은 완전히 별개의 보안 개념을 배우는 것이 아니다.

```text
iptables에서 배운 것
        ↓
Protocol / IP / Port / State / Allow / Deny
        ↓
firewalld에서도 그대로 필요한 방화벽 기본 개념
```

즉, **iptables는 패킷 필터링 원리를 이해하는 데 매우 유용하고, firewalld는 이를 보다 관리하기 쉬운 방식으로 다룬다고 이해하면 좋다.**

# Part 10. 서비스별 Port 치트시트

## 19. 반드시 기억할 대표 Port

| 서비스 | Protocol | Port |
|---|---|---:|
| FTP Control | TCP | 21 |
| SSH | TCP | 22 |
| Telnet | TCP | 23 |
| SMTP | TCP | 25 |
| DNS | TCP/UDP | 53 |
| DHCP Server | UDP | 67 |
| DHCP Client | UDP | 68 |
| HTTP | TCP | 80 |
| POP3 | TCP | 110 |
| NTP | UDP | 123 |
| HTTPS | TCP | 443 |
| SMB | TCP | 445 |
| MariaDB/MySQL | TCP | 3306 |

# Part 11. 패킷 흐름으로 전체 이해하기

## 20. 사용자가 Web 사이트에 접속할 때

```text
1. Client가 www.example7777.com 입력
                    ↓
2. DNS Server에 이름 질의
                    ↓
3. DNS A Record에서 Server IP 반환
                    ↓
4. Client가 Server TCP 80/443으로 연결
                    ↓
5. Server Firewall이 HTTP/HTTPS 허용 여부 검사
                    ↓
6. httpd가 Request 수신
                    ↓
7. 동적 Java 처리가 필요하면 Tomcat/WAS 처리
                    ↓
8. DB 데이터가 필요하면 JDBC를 통해 MariaDB 조회
                    ↓
9. 결과가 Client Browser로 반환
```

이 흐름을 이해하면 DNS, 방화벽, Apache, Tomcat, MariaDB를 **각각 따로 외우지 않아도 된다.**

## 25. Firewall 설정했는데 적용되지 않음

`--permanent` 설정은 영구 구성에 기록되지만 즉시 runtime에 반영되지 않을 수 있으므로 reload를 수행한다.

```bash
firewall-cmd --permanent --add-service=http
firewall-cmd --reload
firewall-cmd --list-all
```

반대로 runtime에만 추가한 규칙은 재부팅/서비스 재시작 이후 유지되지 않을 수 있다.

# Part 14. 면접 / 복습 Q&A

## Q1. Web Server와 WAS의 차이는?

**A.** Web Server는 HTTP 요청과 정적 콘텐츠 제공을 주로 담당하며, WAS는 Servlet/JSP와 같은 동적 애플리케이션 로직을 실행한다. 실습에서는 Apache HTTPD를 Web Server, Tomcat을 WAS로 볼 수 있다.

---

## Q2. DNS의 A Record와 PTR Record 차이는?

**A.** A Record는 Hostname을 IPv4 주소로 변환하는 정방향 조회에 사용하고, PTR Record는 IP 주소를 Hostname으로 변환하는 역방향 조회에 사용한다.

---

## Q3. MX Record가 메일을 직접 전송하는가?

**A.** 아니다. MX Record는 특정 Domain의 Mail Server가 무엇인지 알려주는 DNS Record다. 실제 메일 전달은 SMTP가 수행한다.

---

## Q4. SMTP와 POP3의 차이는?

**A.** SMTP는 메일 송신 및 Mail Server 간 전달에 사용하고, POP3는 Client가 Mail Server에서 메일을 가져오는 데 사용한다.

---

## Q5. FTP에서 TCP 21만 열었는데 파일 전송이 안 될 수 있는 이유는?

**A.** TCP 21은 FTP Control Connection에 사용된다. Passive Mode에서는 데이터 전송을 위한 별도 Passive Port가 필요하므로 서버에 설정한 Passive Port 범위를 방화벽에서도 허용해야 한다.

---

## Q6. Stateful Firewall이란?

**A.** 개별 패킷의 IP/Port만 확인하는 것이 아니라 연결 상태까지 추적하여 NEW, ESTABLISHED, RELATED 등의 상태를 기준으로 패킷을 처리하는 방화벽 방식이다.

---

## Q7. INPUT과 FORWARD의 차이는?

**A.** INPUT은 방화벽이 실행 중인 서버 자신을 목적지로 하는 패킷이고, FORWARD는 해당 시스템을 거쳐 다른 목적지로 전달되는 패킷이다.

---

## Q8. 서비스가 Active인데 Client가 접속하지 못한다. 무엇을 확인할 것인가?

**A.** IP/Route와 기본 통신을 먼저 확인하고, 서비스가 실제 Port에서 LISTEN 중인지 확인한다. 이후 방화벽, 애플리케이션 설정, DNS를 순서대로 점검한다.

```text
IP → Route → Ping → Service → Listen Port → Firewall → Application → DNS
```

---

## Q9. `--permanent`의 의미는?

**A.** firewalld의 영구 설정에 Rule을 기록한다는 의미다. 일반적으로 변경 후 `firewall-cmd --reload`를 수행하여 runtime 구성에 반영한다.

---

## Q10. NFS와 Samba의 대표적인 차이는?

**A.** 둘 다 Network File Sharing을 제공하지만 NFS는 Linux/Unix 환경에서 널리 사용되고 Samba는 SMB/CIFS를 이용해 Windows와 Linux 사이의 파일 공유에 많이 사용된다.

# Part 17. 이번 주에 반드시 가져갈 10문장

1. **서비스 실행과 방화벽 허용은 서로 다른 문제다.**
2. **접속 장애는 IP → Route → Service → Port → Firewall 순서로 좁혀간다.**
3. **NFS는 서버의 공유 디렉터리를 Client가 mount하여 사용하는 구조다.**
4. **Apache는 Web Server, Tomcat은 Java 기반 WAS 역할을 수행할 수 있다.**
5. **JSP는 JDBC를 이용해 MariaDB와 연결할 수 있다.**
6. **DNS의 A는 이름→IP, PTR은 IP→이름, MX는 Mail Server를 지정한다.**
7. **SMTP는 메일 전송, POP3는 메일 수신/가져오기에 사용한다.**
8. **iptables를 통해 Chain, Rule, State라는 방화벽의 기본 원리를 이해한다.**
9. **firewalld에서는 Service 또는 Port 단위로 접근을 허용할 수 있다.**
10. **FTP Passive Port 범위와 방화벽 허용 범위는 반드시 일치시킨다.**

# Final — 이번 주 학습의 의미

이번 주부터 Linux 학습은 단순한 명령어 사용 단계를 넘어섰다.

```text
Linux 기본 명령어
      ↓
사용자 / 권한 / Process
      ↓
Storage / RAID / Package
      ↓
Network
      ↓
Network Service
      ↓
Web / WAS / DB
      ↓
DNS / Mail
      ↓
Firewall
```

이제 각각의 기술을 따로 외우기보다 다음 질문을 반복하는 것이 중요하다.

> **“Client의 패킷이 Server의 Application까지 도달하기 위해 어떤 과정을 거치는가?”**

이 질문에 답할 수 있으면 Network, Service, Port, DNS, Firewall이 하나의 흐름으로 연결된다.

```text
Client
 ↓
Network
 ↓
DNS
 ↓
Firewall
 ↓
Listening Port
 ↓
Daemon / Service
 ↓
Application
 ↓
Database / File / Mail
```

**이번 주의 진짜 핵심은 명령어 개수가 아니라 이 연결 관계를 이해하는 것이다.** 🐧🔥
