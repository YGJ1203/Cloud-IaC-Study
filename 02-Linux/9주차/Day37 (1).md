# 🔥 Linux Firewall 실습 정리 — firewalld
> **날짜:** 2026-08-28  
> **환경:** CentOS Stream 9 / VMware / MobaXterm  
> **범위:** 오늘의 신규 진도인 Firewall 파트만 정리  
> **목표:** Server1·Server2에 구성된 서비스에 Client가 접속할 수 있도록 `firewalld`를 구성하고, Rich Rule을 이용한 세부 접근 제어를 이해한다.

---

## 1. 오늘의 핵심 구조

```text
Client
  │
  │ 접속 요청
  ▼
Server firewalld
  │
  ├─ Zone
  │   └─ public
  │
  ├─ Service 허용
  ├─ Port 허용
  └─ Rich Rule
      ├─ Source
      ├─ Service / Port
      └─ accept / reject / drop
  │
  ▼
Server Service
```

방화벽의 핵심은 다음 질문으로 정리할 수 있다.

> **어떤 트래픽을 허용하고, 어떤 트래픽을 차단할 것인가?**

# 2. firewalld

`firewalld`는 Linux에서 방화벽 정책을 관리하기 위한 서비스이다.

상태 확인:

```bash
systemctl status firewalld
```

시작:

```bash
systemctl start firewalld
```

활성 Zone 확인:

```bash
firewall-cmd --get-active-zones
```

public Zone 전체 확인:

```bash
firewall-cmd --zone=public --list-all
```

---

# 3. Zone

firewalld에서는 네트워크 연결을 **Zone** 단위로 관리한다.

오늘 실습에서는 주로:

```bash
--zone=public
```

을 사용한다.

```text
NIC / Connection
       │
       ▼
    public Zone
       │
       ├─ Service
       ├─ Port
       └─ Rich Rule
```

---

# 4. Runtime과 Permanent

## Runtime 설정

현재 실행 중인 firewalld에 적용된다.

```bash
firewall-cmd --zone=public --add-service=http
```

## Permanent 설정

영구 설정으로 저장한다.

```bash
firewall-cmd --permanent --zone=public --add-service=http
```

`--permanent` 설정 후에는 Runtime에 반영하기 위해:

```bash
firewall-cmd --reload
```

를 실행한다.

### 암기

```text
--permanent
     ↓
영구 설정 저장
     ↓
firewall-cmd --reload
     ↓
현재 방화벽에 반영
```

---

# 5. Service 허용

서비스 이름을 이용해 접근을 허용할 수 있다.

```bash
firewall-cmd --permanent --zone=public --add-service=http
```

여러 서비스:

```bash
firewall-cmd --permanent --zone=public \
  --add-service={ssh,http,https,dns}
```

확인:

```bash
firewall-cmd --zone=public --list-services
```

사용 가능한 서비스 확인:

```bash
firewall-cmd --get-services
```

---

# 6. Port 허용

포트를 직접 지정할 수도 있다.

```bash
firewall-cmd --permanent --zone=public --add-port=8080/tcp
```

범위:

```bash
firewall-cmd --permanent --zone=public --add-port=8080-8083/tcp
```

확인:

```bash
firewall-cmd --zone=public --list-ports
```

# 9. Service와 Port

HTTP처럼 firewalld에 서비스 정의가 있는 경우:

```bash
firewall-cmd --permanent --add-service=http
```

특정 포트를 직접 허용하려면:

```bash
firewall-cmd --permanent --add-port=8080/tcp
```

```text
Service
 └─ 서비스 이름으로 정책 관리

Port
 └─ 프로토콜 + 포트 번호를 직접 지정
```

오늘 실습에서는 표준 서버 서비스는 `--add-service`, Tomcat 및 별도 웹 포트와 FTP Passive 범위는 `--add-port`로 구성했다.

---

# 10. ⭐ Rich Rule

Rich Rule은 일반적인 Service/Port 허용보다 **더 세부적인 조건을 지정하는 규칙**이다.

기본적인 형태:

```bash
firewall-cmd --permanent --zone=public \
  --add-rich-rule='rule family="ipv4" source address="192.168.2.201" service name="ssh" accept'
```

구조:

```text
rule
 │
 ├─ family="ipv4"
 │
 ├─ source address="..."
 │
 ├─ service name="..."
 │      또는
 │   port port="..." protocol="..."
 │
 └─ accept / reject / drop
```

즉:

```text
누가?
 ↓
source

어디로/무엇을?
 ↓
service / port

어떻게 처리?
 ↓
accept / reject / drop
```

---

# 11. Rich Rule 예시

## 특정 Client의 SSH 허용



```bash
firewall-cmd --permanent --zone=public \
```

```bash

```

확인:

```bash
firewall-cmd --zone=public --list-rich-rules
```

# 12. accept / reject / drop

| 동작 | 의미 | 상대방에게 거부 응답 |
|---|---|---|
| `accept` | 허용 | - |
| `reject` | 차단 | O |
| `drop` | 패킷 폐기 | X |

### ACCEPT

```text
Client ───────────→ Server
          통과
```

### REJECT

```text
Client ───────────X Server
       ← 거부 응답
```

### DROP

```text
Client ───────────X Server

응답 없음...
```

# 14. Client에서 Nmap으로 검증

오늘 실습에서 Client1은 Server1(`192.168.2.203`)을 Nmap으로 스캔했다.

```bash
nmap -sS -sV 192.168.2.203
```

옵션:

| 옵션 | 의미 |
|---|---|
| `-sS` | TCP SYN Scan |
| `-sV` | 서비스/버전 탐지 |

실습 과정에서는 방화벽 상태에 따라 다수의 포트가 `filtered`로 나타났고, 이후 정책을 적용하면서 FTP, SSH, Telnet, DNS, HTTP, RPCBind, Samba, HTTPS, NFS, MySQL, Tomcat 등이 `open`으로 확인되는 과정이 기록되었다.

---

# 15. Nmap 상태 해석

## open

```text
PORT     STATE
80/tcp   open
```

해당 포트에서 서비스가 연결을 받을 수 있는 상태.

## closed

```text
8081/tcp closed
```

호스트에는 도달했지만 해당 포트가 열린 서비스로 확인되지 않은 상태.

## filtered

```text
PORT   STATE
80/tcp filtered
```

필터링 때문에 Nmap이 포트 상태를 명확하게 판단하지 못한 상태.

### 실습에서 기억할 포인트

```text
방화벽 허용
    ≠
서비스 실행
```

방화벽에서 포트를 허용해도 실제 서비스가 해당 포트에서 동작하지 않으면 Nmap 결과가 `open`으로 나타나는 것은 아니다.

# 19. 방화벽 트러블슈팅 루틴

```text
① Server 서비스가 실행 중인가?
          ↓
② 해당 Port가 LISTEN 중인가?
          ↓
③ firewalld가 실행 중인가?
          ↓
④ 인터페이스가 어느 Zone에 속하는가?
          ↓
⑤ Service / Port / Rich Rule이 맞는가?
          ↓
⑥ Client에서 Nmap
          ↓
⑦ 실제 서비스 접속 테스트
```

주요 명령:

```bash
systemctl status firewalld

ss -lntup

firewall-cmd --get-active-zones

firewall-cmd --zone=public --list-all

firewall-cmd --zone=public --list-services

firewall-cmd --zone=public --list-ports

firewall-cmd --zone=public --list-rich-rules
```

Client:

```bash
nmap -sS -sV <SERVER_IP>
curl -I http://<SERVER_IP>
ftp <SERVER_IP>
telnet <SERVER_IP>
ssh <SERVER_IP>
nslookup <DOMAIN>
```

# 21. 시험 / 면접 Q&A

### Q1. firewalld에서 Zone이란?

네트워크 연결에 서로 다른 방화벽 정책을 적용하기 위한 논리적 영역이다.

### Q2. `--permanent` 옵션의 역할은?

방화벽 정책을 영구 설정으로 저장하기 위해 사용한다.

### Q3. Service와 Port 방식의 차이는?

Service는 firewalld의 서비스 정의를 이용하고, Port 방식은 프로토콜과 포트 번호를 직접 지정한다.

### Q4. Rich Rule은 왜 사용하는가?

출발지 주소, 서비스, 포트 등 여러 조건을 이용해 일반 Service/Port 규칙보다 세밀한 접근 제어를 구성하기 위해 사용한다.

### Q5. reject와 drop의 차이는?

`reject`는 차단하면서 거부 응답을 보내고, `drop`은 패킷을 폐기하여 응답하지 않는다.

### Q6. 방화벽에서 포트를 허용했는데 Nmap에서 closed가 나오는 이유는?

방화벽의 허용 규칙과 실제 서버 프로세스의 Listening 상태는 별개이기 때문이다.

### Q7. Nmap의 filtered는 무엇을 의미하는가?

패킷 필터링 등의 이유로 Nmap이 해당 포트의 상태를 확정하기 어려운 경우를 의미한다.

# 22. 🔥 초압축 암기

```text
firewalld
│
├─ Zone
│   └─ public
│
├─ Service
│   └─ --add-service
│
├─ Port
│   └─ --add-port
│
├─ Permanent
│   └─ --permanent
│
├─ 적용
│   └─ --reload
│
└─ Rich Rule
    ├─ family
    ├─ source
    ├─ service / port
    └─ accept / reject / drop
```

### 핵심 한 줄

> **Service/Port 규칙은 “무엇을 열 것인가”를 정하고, Rich Rule은 “누구에게 무엇을 어떻게 허용·차단할 것인가”를 더 세밀하게 표현한다.**

## 오늘의 결론 😎

오늘의 **신규 학습 범위는 Firewall**이다.

```text
Server Service
      ↑
   firewalld
      ↑
Service / Port / Rich Rule
      ↑
    Client
```

Server에서 서비스를 구축하는 것만으로 끝나는 것이 아니라, **Client가 실제로 접근할 수 있도록 필요한 트래픽을 방화벽 정책에서 허용하고 Nmap·curl·nslookup 등으로 검증하는 것**까지가 오늘 Firewall 실습의 핵심이다.

> 이후 Storage 머신 생성, RAID 10, NFS 및 Server1/Server2 마운트 실습은 **Firewall의 연장 진도가 아니라 기존 Linux 과정의 처음부터 다시 진행한 복습 파트**이므로 이 문서에서는 분리하였다.
