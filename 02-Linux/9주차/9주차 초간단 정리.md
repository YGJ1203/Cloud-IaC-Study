## 1. NFS / Samba — 파일 공유

### NFS
- Linux/Unix 계열 시스템 간 디렉터리 공유에 주로 사용
- 서버가 디렉터리를 `export`하고 클라이언트가 `mount`하여 사용
- `rw` : 읽기/쓰기
- `ro` : 읽기 전용

```bash
mount -t nfs SERVER_IP:/공유디렉터리 /마운트지점
```

### Samba
- Linux ↔ Windows 간 파일/디렉터리 공유에 주로 사용
- SMB/CIFS 프로토콜 사용

> **핵심:** NFS와 Samba 모두 원격 자원을 로컬 디렉터리처럼 사용할 수 있게 해주는 파일 공유 서비스이다.

## 2. HTTPD / Tomcat / MariaDB — 웹 서비스 구조

```text
Client
  ↓ HTTP/HTTPS
Apache HTTPD
  ↓
Tomcat
  ↓ JSP/JDBC
MariaDB
```

- **Apache HTTPD** : 웹 서버(Web Server)
- **Tomcat** : Java/JSP를 처리하는 WAS
- **MariaDB** : 데이터를 저장하는 DBMS
- **JDBC** : Java 애플리케이션과 DB를 연결

```text
jdbc:mariadb://localhost:3306/testdb
```

> **핵심:** Web Server → WAS → DB 구조와 각 계층의 역할을 구분한다.

---

## 3. DNS — 이름을 IP 주소로 변환

### 주요 레코드

| Record | 역할 |
|---|---|
| A | 도메인 → IPv4 |
| PTR | IP → 도메인 |
| NS | DNS 서버 지정 |
| MX | 메일 서버 지정 |
| SOA | Zone 기본 정보 |

- **정방향 조회** : Domain → IP
- **역방향 조회** : IP → Domain

```bash
nslookup example7777.com
```

> **핵심:** DNS는 단순히 웹 주소만 변환하는 것이 아니라 메일 서버 등의 서비스 위치를 찾는 데에도 사용된다.

---

## 4. Mail — SMTP / POP3

- **SMTP** : 메일 전송
- **POP3** : 서버에 저장된 메일 수신
- **MX Record** : 해당 도메인의 메일 서버 지정

```text
DNS MX 조회
    ↓
Mail Server 확인
    ↓
SMTP로 메일 전달
    ↓
POP3 등을 이용해 메일 확인
```

> **핵심:** DNS와 Mail은 별개의 서비스이지만 MX 레코드를 통해 서로 연결된다.

---

## 5. iptables — 패킷 기반 방화벽

### 주요 Chain

- `INPUT` : 외부 → 현재 서버
- `OUTPUT` : 현재 서버 → 외부
- `FORWARD` : 서버를 통과하는 패킷

### 주요 Target

- `ACCEPT` : 허용
- `DROP` : 폐기

```bash
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

### Stateful Firewall

기존 연결과 관련된 패킷을 상태 기반으로 판단할 수 있다.

```bash
-m conntrack --ctstate ESTABLISHED,RELATED
```

> **핵심:** IP, Protocol, Port뿐 아니라 **연결 상태(Connection State)**까지 이용해 패킷을 제어할 수 있다.

---

## 6. firewalld — Zone / Service 기반 방화벽

iptables보다 관리자가 이해하기 쉬운 **Zone / Service / Port** 중심의 방화벽 관리 방식을 제공한다.

### Service 허용

```bash
firewall-cmd --permanent --add-service=http
```

### Port 허용

```bash
firewall-cmd --permanent --add-port=8080/tcp
```

### 적용

```bash
firewall-cmd --reload
```

### 확인

```bash
firewall-cmd --list-all
```

> **핵심:** 가능하면 표준 서비스는 `--add-service`, 별도의 애플리케이션 포트는 `--add-port`로 관리한다.

## 8. 서버 접속 장애 점검 순서 🔥

```text
1. IP 주소 확인
        ↓
2. Routing 확인
        ↓
3. ping으로 통신 확인
        ↓
4. 서비스 실행 여부 확인
        ↓
5. Listen Port 확인
        ↓
6. Firewall 확인
        ↓
7. 서비스 설정 파일 확인
        ↓
8. DNS 등 상위 서비스 확인
```

### 자주 사용할 명령어

```bash
ip addr
ip route
ping IP
systemctl status SERVICE
ss -lntup
firewall-cmd --list-all
```

> **핵심:** 접속이 안 된다고 바로 방화벽부터 수정하지 말고 **네트워크 → 서비스 → 포트 → 방화벽 → 애플리케이션 설정** 순서로 원인을 좁힌다.
