# 2. Linux Package Management

## RPM

Red Hat 계열 Linux의 기본 패키지 관리 방식이다.

```bash
rpm -ivh package.rpm
rpm -Uvh package.rpm
rpm -e package
rpm -qa
rpm -qi package
rpm -ql package
```

### 핵심 옵션

| 옵션   | 의미       |
| ---- | -------- |
| `-i` | 설치       |
| `-U` | 업그레이드/설치 |
| `-e` | 삭제       |
| `-q` | 조회       |
| `-a` | 전체       |
| `-i` | 정보 출력    |
| `-l` | 파일 목록    |
| `-v` | 상세 출력    |
| `-h` | 진행 상황 표시 |

RPM의 중요한 특징은 **의존성을 자동으로 해결해 주지 않는다는 것**이다.

예를 들어 `php`가 `php-common`을 필요로 한다면 필요한 패키지를 직접 준비해야 할 수 있다.

# 3. YUM / DNF

RPM보다 실무에서 편리하게 사용할 수 있는 상위 패키지 관리 도구이다.

```bash
yum install 패키지명
yum remove 패키지명
yum reinstall 패키지명
yum info 패키지명
yum list installed
```

최근 RHEL 계열에서는 주로 `dnf`를 사용한다.

```bash
dnf install 패키지명
dnf remove 패키지명
```

### RPM과 YUM/DNF의 가장 큰 차이

```text
rpm
 ↓
개별 패키지 직접 관리

yum / dnf
 ↓
Repository 확인
 ↓
필요한 패키지 검색
 ↓
Dependency 확인
 ↓
의존 패키지까지 함께 설치
```

따라서 일반적인 패키지 설치에서는 `yum` 또는 `dnf`가 훨씬 편리하다.

# 4. Debian 계열 패키지 관리

Red Hat 계열과 Debian 계열의 명령어는 다르다.

| Red Hat   | Debian |
| --------- | ------ |
| rpm       | dpkg   |
| yum / dnf | apt    |

예:

```bash
apt -y install net-tools iproute2 bind9-dnsutils iputils-ping curl
```

설치 여부 확인:

```bash
dpkg -l net-tools iproute2 bind9-dnsutils iputils-ping curl
```

패키지가 설치한 파일 확인:

```bash
dpkg -L net-tools
```

# 6. Linux Storage 기본 흐름

스토리지를 사용할 때 가장 중요한 흐름이다.

```text
Disk
 ↓
Partition
 ↓
Filesystem
 ↓
Mount
 ↓
사용
```

대표적인 명령어:

```bash
fdisk -l
fdisk /dev/sdb
mkfs -t ext4 /dev/sdb1
mkdir /data
mount /dev/sdb1 /data
df -h
```

즉,

```text
/dev/sdb
   ↓ fdisk
/dev/sdb1
   ↓ mkfs
ext4
   ↓ mount
/data
```

# 7. /etc/fstab

`mount` 명령으로 직접 마운트하면 재부팅 후 마운트 상태가 유지되지 않는다.

자동 마운트가 필요하다면 `/etc/fstab`을 사용한다.

구조:

```text
장치    마운트포인트    파일시스템    옵션    dump    fsck
```

예:

```text
/dev/sdb1 /data ext4 defaults 0 0
```

실습에서는 수정 후 바로 재부팅하기보다 먼저 다음 명령으로 검증하는 습관이 중요하다.

```bash
mount -a
```

⚠️ `/etc/fstab`을 잘못 작성하면 부팅 과정에서 문제가 발생할 수 있다.

# 8. LVM

LVM은 여러 저장장치를 논리적으로 관리하기 위한 기술이다.

구조:

```text
Physical Disk
     ↓
    PV
     ↓
    VG
     ↓
    LV
     ↓
Filesystem
     ↓
Mount
```

## PV 생성

```bash
pvcreate /dev/sdb1
```

확인:

```bash
pvs
pvdisplay
```

## VG 생성

```bash
vgcreate vg01 /dev/sdb1
```

확인:

```bash
vgs
vgdisplay
```

## LV 생성

```bash
lvcreate -L 1G -n lv01 vg01
```

확인:

```bash
lvs
lvdisplay
```

파일시스템 생성:

```bash
mkfs -t ext4 /dev/vg01/lv01
```

마운트:

```bash
mkdir /data
mount /dev/vg01/lv01 /data
```

### LVM 핵심

```text
PV = 실제 디스크/파티션을 LVM용으로 준비

VG = 여러 PV를 하나의 저장 공간 Pool로 묶음

LV = VG에서 실제 사용할 논리 볼륨을 생성
```

# 9. RAID

RAID는 여러 디스크를 조합하여 **성능 또는 장애 대응 능력**을 확보하는 기술이다.

이번 주에 학습한 RAID:

```text
RAID 0
RAID 1
RAID 5
RAID 6
RAID 0+1
RAID 1+0
```

---

# 10. RAID 0

Striping 방식.

```text
Disk A    Disk B    Disk C
  A1        A2        A3
  B1        B2        B3
```

### 특징

* 최소 2개 디스크
* 성능 향상
* 전체 용량 사용 가능
* 장애 복구 기능 없음

디스크 하나만 고장 나도 전체 데이터가 손상될 수 있다.

```bash
mdadm --create /dev/md0 \
--level=0 \
--raid-devices=3 \
/dev/sdc1 /dev/sdd1 /dev/sde1
```

---

# 11. RAID 1

Mirroring 방식.

```text
Disk A       Disk B

 DATA   →    DATA
```

### 특징

* 최소 2개 디스크
* 동일 데이터를 복제
* 장애 대응 가능
* 실제 사용 가능 용량 감소

---

# 12. RAID 5

Striping + Distributed Parity.

```text
Disk A    Disk B    Disk C

Data      Data      Parity
Data      Parity    Data
Parity    Data      Data
```

### 특징

* 최소 3개 디스크
* 디스크 1개 장애 허용
* 용량 효율과 안정성의 균형

사용 가능 용량:

```text
(N - 1) × Disk Size
```

---

# 13. RAID 6

RAID 5보다 Parity를 하나 더 사용한다.

### 특징

* 최소 4개 디스크
* 디스크 2개 장애 허용

사용 가능 용량:

```text
(N - 2) × Disk Size
```

RAID 5보다 안정성이 높지만 Parity 계산 부담도 더 크다.

---

# 14. RAID 0+1 vs RAID 1+0

## RAID 0+1

```text
RAID 0
  ↓
Mirror
```

즉,

> Striping한 그룹을 Mirroring

## RAID 1+0 (RAID 10)

```text
RAID 1
  ↓
Stripe
```

즉,

> Mirroring한 그룹들을 Striping

일반적으로 RAID 10이 장애 대응 측면에서 더 유연하게 평가된다.

---

# 15. mdadm

Linux Software RAID 관리 명령어.

생성:

```bash
mdadm --create /dev/md0 \
--level=0 \
--raid-devices=3 \
/dev/sdc1 /dev/sdd1 /dev/sde1
```

확인:

```bash
cat /proc/mdstat
mdadm --detail /dev/md0
mdadm --detail --scan -v
```

파일시스템 생성:

```bash
mkfs -t ext4 /dev/md0
```

마운트:

```bash
mkdir /mnt/raid0
mount /dev/md0 /mnt/raid0
```

---

# 16. RAID 삭제

마운트 해제:

```bash
umount /dev/md0
```

RAID 중지:

```bash
mdadm --stop /dev/md0
```

Superblock 확인:

```bash
mdadm --examine /dev/sdc1
```

RAID Metadata 제거:

```bash
mdadm --zero-superblock /dev/sdc1
```

⚠️ `--zero-superblock`은 해당 장치의 RAID 메타데이터를 제거하므로 대상 장치를 반드시 확인해야 한다.

# 17. Backup

백업은 크게 세 가지 방식으로 이해할 수 있다.

```text
Full Backup
Incremental Backup
Differential Backup
```

---

# 18. Full Backup

모든 데이터를 백업한다.

```text
월요일

A
B
C
D

↓ Full Backup

A
B
C
D
```

### 장점

복구가 단순하다.

### 단점

백업 시간과 저장 공간을 많이 사용한다.

---

# 19. Incremental Backup

마지막 백업 이후 변경된 데이터만 백업한다.

```text
월 Full
 ↓
화 변경분
 ↓
수 변경분
 ↓
목 변경분
```

복구:

```text
Full
 +
화 Incremental
 +
수 Incremental
 +
목 Incremental
```

### 장점

백업 속도가 빠르고 용량이 적다.

### 단점

복구 과정이 복잡하다.

---

# 20. Differential Backup

마지막 **Full Backup 이후 변경된 모든 데이터**를 백업한다.

```text
월 Full

화 → 월 이후 변경분

수 → 월 이후 변경분

목 → 월 이후 변경분
```

복구:

```text
Full
+
가장 최근 Differential
```

### 핵심 비교

| 방식           | 백업 속도 | 저장 공간 |     복구 |
| ------------ | ----: | ----: | -----: |
| Full         |    느림 |     큼 |     쉬움 |
| Incremental  |    빠름 |    작음 |     복잡 |
| Differential |    중간 |    중간 | 비교적 쉬움 |

# 21. tar Incremental Backup

GNU `tar`에서는 snapshot 파일을 이용할 수 있다.

```bash

```

`-g` 옵션으로 snapshot 정보를 기록하여 변경된 파일을 판단할 수 있다.

# 30. SSH

Secure Shell.

기본 포트:

```text
TCP 22
```

원격 Linux 서버에 안전하게 접속하기 위한 대표적인 프로토콜이다.

```bash
ssh user@server
```

SSH는 이후 학습한 SCP와 SFTP의 기반이 된다.

---

# 31. SCP

Secure Copy.

SSH를 기반으로 파일을 복사한다.

```bash
scp file.txt user@server:/tmp/
```

원격 → 로컬:

```bash
scp user@server:/tmp/file.txt .
```

특징:

```text
SSH 기반
TCP 22
암호화
간단한 파일 복사에 적합
```

---

# 32. SFTP

SSH File Transfer Protocol.

접속:

```bash
sftp user@server
```

대표 명령어:

```bash
ls
cd
pwd
get
put
mkdir
rm
exit
```

특징:

```text
SSH 기반
TCP 22
암호화
FTP와 비슷한 대화형 파일 관리 가능
```

---

# 33. FTP

File Transfer Protocol.

기본 Control Port:

```text
TCP 21
```

FTP는 기본적으로 암호화되지 않는다.

```text
FTP
→ 파일 전송 프로토콜

SFTP
→ SSH 기반 파일 전송

둘은 이름만 비슷할 뿐 서로 다른 프로토콜이다.
```

# 36. FTP 응답 코드

FTP 서버는 숫자 형태의 응답 코드를 반환한다.

대표적인 구조:

```text
1xx → 처리 진행
2xx → 성공
3xx → 추가 입력 필요
4xx → 일시적 오류
5xx → 영구적 오류
```

예:

```text
220 → Service ready
230 → Login successful
331 → Password required
530 → Login incorrect
```

FTP 문제를 해결할 때 메시지뿐 아니라 **응답 코드**를 같이 확인하면 좋다.

# 37. Anonymous FTP

FTP에서는 익명 사용자 접속을 허용할 수도 있다.

vsftpd 설정 파일:

```bash
/etc/vsftpd/vsftpd.conf
```

대표 설정:

```text
anonymous_enable=YES
```

설정을 변경했다면:

```bash
systemctl restart vsftpd
```

⚠️ 실제 서버에서는 익명 접근 허용 범위와 쓰기 권한을 신중하게 설정해야 한다.

# 38. CentOS 6 vs CentOS 7+

서비스 관리 방식의 큰 변화.

## CentOS 6

```bash
service vsftpd start
service vsftpd stop
service vsftpd restart
service vsftpd status
```

주로 SysV init 기반 관리 방식.

## CentOS 7+

```bash
systemctl start vsftpd
systemctl stop vsftpd
systemctl restart vsftpd
systemctl status vsftpd
```

`systemd` 기반이다.

# 39. systemd

CentOS 7 이후 Linux에서 서비스와 시스템 상태를 관리하는 핵심 구성요소.

```text
systemd
 │
 ├── service
 ├── socket
 ├── target
 ├── timer
 ├── mount
 └── 기타 Unit
```

따라서 `systemctl`은 단순히 서비스만 제어하는 명령어가 아니다.

# 40. Service vs Socket

## `.service`

실제 서비스 프로세스를 정의한다.

예:

```text

vsftpd.service
```

## `.socket`

특정 Socket을 감시하다가 연결 요청이 들어왔을 때 관련 서비스를 시작하도록 구성할 수 있다.

개념적으로:

```text
Client
 ↓
Socket
 ↓
systemd
 ↓
Service Start
```

# 42. xinetd 방식

과거 Linux에서 많이 사용된 Super Server 방식.

 ↓

# 47. 시험/면접식 핵심 질문

### Q1. `rpm`과 `yum`의 차이는?

`rpm`은 개별 RPM 패키지를 직접 관리하고, `yum`은 Repository를 기반으로 의존성을 함께 해결한다.

### Q2. LVM 구조는?

```text
PV → VG → LV
```

### Q3. RAID 0의 장단점은?

Striping으로 성능과 용량 효율은 높지만 장애 복구 기능이 없다.

### Q4. RAID 5는 몇 개의 디스크 장애를 허용하는가?

1개.

### Q5. RAID 6은?

2개.

### Q6. Incremental과 Differential 차이는?

Incremental은 **직전 백업 이후 변경분**, Differential은 **마지막 Full Backup 이후 변경분**을 저장한다.

### Q7. `at`과 `cron`의 차이는?

```text
at   → 일회성
cron → 반복
```

### Q8. SCP와 SFTP의 공통점은?

둘 다 SSH 기반이며 일반적으로 TCP 22를 사용한다.

### Q9. FTP와 SFTP는 같은 프로토콜인가?

아니다.

```text
FTP  → 독립적인 File Transfer Protocol
SFTP → SSH File Transfer Protocol
```

### Q10. CentOS 6과 CentOS 7의 서비스 관리 차이는?

```text
CentOS 6 → service
CentOS 7+ → systemctl
```

### Q11. `/etc/fstab`은 왜 사용하는가?

부팅 시 파일시스템을 자동으로 마운트하기 위해 사용한다.

### Q12. `ss -lntp`는 왜 사용하는가?

현재 TCP Listening Port와 관련 프로세스를 확인하기 위해 사용한다.

# 48. 이번 주 반드시 기억할 10개

```text
① Disk → Partition → Filesystem → Mount

② LVM = PV → VG → LV

③ RAID 0 = 성능 / 장애 대응 X

④ RAID 1 = Mirroring

⑤ RAID 5 = 1 Disk Failure 허용

⑥ RAID 6 = 2 Disk Failure 허용

⑦ Incremental = 직전 Backup 이후 변경분

⑧ Differential = Full Backup 이후 변경분

⑨ SCP / SFTP = SSH 기반 TCP 22

⑩ CentOS 7+ Service 관리 = systemctl
```
